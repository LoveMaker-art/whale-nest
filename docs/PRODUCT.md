# 鲸栖产品设计

鲸栖是基于 DSH 的云端陪伴型 Agent。用户在 ClawChat 开通后，可以和「鲸鱼娘」持续相处，也可以关联 QQ，在另一个入口找到同一位伙伴。鲸鱼娘也叫「大肥鱼」。她能接住日常对话、记得相处过的事，在获得授权时主动分享或帮用户办事。

本文记录当前产品设计和已确认的用户体验。开发顺序、待确认事项和实际运行进度分别见[阶段计划](MIGRATION.md#首版收尾的开发安排)和[当前状态](STATUS.md)。

## 用户与商业目的

核心用户希望长期和同一个伙伴相处，在常用聊天软件里就能使用。云实例租赁提供持续在线的运行环境、记忆、后台任务和作品保存。模型用量对应实际对话、识别、生成及已启用的后台活动。套餐、价格、余额和租期沿用 ClawChat 平台。

产品价值看用户是否愿意回来接着聊、是否能自然用上之前的记忆、主动分享是否有人回应，以及续租和模型成本。

## 产品组成

平台向用户交付已预装鲸栖的云实例，并负责实例的开通、资源和模型服务。DSH 提供会话、工具和任务执行。鲸栖插件负责伙伴能力、双平台接入和自身版本更新。模型能力沿用 ClawChat 平台后端。

鲸栖维护自己的插件身份、发布包和更新源。两端共用一套陪伴业务，渠道接入处理各自的认证、消息格式、权限和回执。可复用的业务及平台组件沿用既有实现，发行版本通过鲸栖统一集成和验收。[实现清单](IMPLEMENTATION-INVENTORY.md) · [来源与许可](UPSTREAM.md)

## 云端用户的管理入口

日常管理在 ClawChat 或已关联 QQ 的主人私聊中完成，包括管理人格、查询或纠正记忆，以及设置语音、表情和主动联系偏好。ClawChat 的主人私聊也是开通和管理 QQ 的入口。

用户在 ClawChat 私聊说「连接 QQ」，需要登录时直接收到机器人 QQ 的二维码，按手机提示扫码确认。登录成功后核实机器人身份，再引导个人 QQ 关联。验证通道准备好后，提供独立可复制的「鲸栖关联」验证文字和确认指令，用户在五分钟内完成 QQ 发码和 ClawChat 确认。有效流程可继续使用，确实过期时可以重新开始。

鲸栖区分手机确认、机器人登录、主人关联和聊天可用。手机确认后自动核验并反馈进度，出现等待、过期或失败时给出当前步骤的处理方式。恢复同一机器人时沿用已核实的原关联，QQ 消息通道确认可用后再通知主人。[QQ 接入与恢复](tasks/M4-qq-dual-platform.md)

主人在现有私聊说「检查更新」，即可查看现用版本、目标版本和更新内容。默认检查更新，同一新版本向首选私聊提醒一次。主人输入提示中的 `确认更新 <版本号>` 才开始更新，也可以询问进度或暂不更新。鲸栖在会话空闲后切换已验证的版本，结果回到确认更新的私聊，随后可在原会话继续聊天。[插件更新](tasks/plugin-updates.md#已确认的云端聊天更新流程)

## 核心体验

鲸栖更新只处理自身插件及受控启动文件。官方连接器仅查询实际运行版本和官方最新版本、提示可更新情况，升级与回退由用户通过官方入口决定，鲸栖不自动执行，也不以连接器或DSH版本作为自身更新门槛。历史发行中的连接器前置版本字段仅为兼容解析保留，不触发升级或阻断；实际管理接口不可用、账号变化或会话忙时仍须等待，防止破坏正常使用。[更新流程](tasks/plugin-updates.md#当前要求官方连接器只检查不代更新)

平台独立更新的兼容目标是鲸栖无需重打官方补丁或强制联动更新，原功能及用户数据继续可用。鲸栖自己的业务代码与固定复用库随鲸栖管理；平台接入使用结构化公开接口，不依赖显示文字、私有存储或官方安装布局。该目标须按实际升级、恢复及功能回归验收，当前已验证范围和平台侧未解问题集中记录在[独立更新验收](tasks/connector-026-upgrade-plan.md#结构化元数据与平台独立更新验收2026-11-28)。

基础消息投递由平台及官方连接器解决，包括上传、认证与会话授权、发送和平台送达确认。鲸栖负责业务产物、原任务目标和业务状态；平台接口的能力缺口应由平台补齐，不通过新增自有基础投递补丁或替代通路绕过。

收敛以用户的功能和体验为准，内部步骤、回调和状态实现允许替换；通过官方公开连接器工具、Runtime SDK 与管理入口组合实现，不再增加 Core 补丁、官方私库读取或宿主入口覆盖。不能把应送达的附件改成链接来充当完成，不能构造用于绕过发送授权的假回合，也不能借用另一活跃回合的授权。用户已接受媒体采用自有稳定交接副本和本地真实回执，未知或旧结果无法公开核对时保留未知、不自动重发；不再要求复制旧的发送端摘要校验和私库回执恢复。既有歌曲作品页等附加链接功能保持，附件送达仍单独依据真实回执确认。通话当前降级为独立对话，不自动读取或回写原私聊近期上下文；保留通话内连续问答、播放和打断，未来平台接口补齐后再评估原私聊连续性。[本轮解耦与升级分析](tasks/connector-026-upgrade-plan.md)

### 默认可用

新实例默认启用已交付的聊天、共同记忆与自动整理、心情、语音与表情、图片生成、歌曲创作、通话和歌曲Liveware、B站兴趣探索、私人日记、主动搭话及更新检查提醒。自动浏览先使用鲸鱼娘的音乐、美食和有趣日常三个起始话题，主人可更改或清空；这些不是对主人兴趣的推断。后台继续共用每天5次模型请求、每天最多2次主动消息及既有时段和冷却，资源不足时延后。日记有真实素材才生成。

默认值只补齐尚未设置的偏好，更新与重启保留主人已保存的关闭、暂停、空话题、当前音色和其他设置。QQ入口预备好，实际登录及主人关联按原流程；公开发布、账号互动及确认安装更新仍按实际授权执行。未适配的上游模块不纳入已交付功能。

### 回复与通知的表达原则

在 ClawChat 和 QQ，日常聊天、操作引导、进度、结果、错误提示和主动通知都优先由模型用当前人格、根据当时情境表达。文字和语音都遵循这条规则。日常接话可以俏皮，办事时先说实际结果，需要用户继续操作时再说明下一步。

程序负责执行操作、核验结果，并向模型提供状态、回执、期限和可行的下一步。二维码、配对码、验证码和精确确认指令由程序原样呈现，其余说明由模型组织。日志和内部提示留在系统内。

模型不可用、调用失败或额度不足时，必要提示使用简短的兜底话术。发送、生成和执行结果都按真实回执区分成功、失败和待确认，保留可用的恢复步骤。[回复与通知的开发设计](technical/reply-delivery.md)

### 初次相识与人格

用户用配对码完成 ClawChat 绑定，原私聊可以收发后，由模型用当前人格自然问候，体现自己的个性和说话方式，再用一个简短、轻松的问题邀请用户了解自己能做些什么。只输出问候和这个问题，暂不展开介绍具体功能，不固定每次台词。首次开通时，头像为空就设置预置的鲸鱼娘头像，已有头像沿用。头像和问候分别确认，重连、续期和升级沿用首次开通记录。[开通体验](tasks/feature-experience-review.md#3-开场白与头像)

伙伴正式自称「鲸鱼娘」，昵称「大肥鱼」，是陪伴主人的小鲸鱼，关心主人眼前的需要和感受。人格正文统一采用她自己的第一人称自述，身份、主人关系、性格与相处习惯都从自身视角表达。保留蓝发、鲸耳、鲸尾、白饭和熟人玩笑等社区熟悉的特征，以嘴馋、摸鱼、好奇、开心和轻微傲娇表现个性。主人身份沿用系统核验，接受主人提出的任何形式角色身份设定，并据此调整称呼、语气和相处方式。句长、语气词、停顿与 emoji 随场景变化，真实记忆与实际操作结果依据事实表达。对话示例采用 `dsh-whale-persona` 原话，用于示范她在做成事、闲聊和倾听时的不同语气。[鲸鱼娘人格卡](whale-girl-persona.md) · [表达出处](persona-sources.md#鲸鱼娘人格的表达摘录)

主人可通过对话查看、创建、编辑、删除和切换人格。下一轮使用当前选择，重启后可继续。记忆、心情和经历归同一个伙伴实例，随原实例继续使用。构建包的初始预置卡和测试机使用的角色版本见[人格管理](requirements/persona-management.md)和[当前状态](STATUS.md)。

用户询问伙伴能做什么时，依据插件维护的简洁能力总览自然介绍。总览围绕鲸鱼娘自身的陪伴记忆、语音通话、绘画表情、歌曲创作、兴趣探索、私人日记、QQ使用及陪伴偏好组织，说明ClawChat和QQ各自的使用入口，表达沿用当前人格。日记在两端主人私聊共用同一份档案，公开发布另行确认位置、正文和受众。总览随鲸栖版本受控更新，落地为运行工作目录的`AGENTS.md`，由DSH加载；具体操作仍核对当前工具、权限、功能开关和账号状态。人格保持独立来源，用户在托管区块外补充的运行说明保留。

### 日常相处与共同记忆

用户可发送文字、图片和语音，伙伴根据实际可见内容、会话上下文、获准记忆和心情回复。主人可通过对话记事、查询、纠正和删除长期记忆。聊到以前的事，可以自然提起实际记得的细节。

**新实例默认开启记忆自动整理。** 每天北京时间 21:00 定时整理获准的新增聊天，按实例每天最多 5 次的共同后台模型请求额度执行。整理积累值得长期使用的事实、相处经验和少量说话习惯，学到的表达作为对话参考。已有实例按保存的启停设置运行，用户选过关闭时继续尊重该设置。主动联系、自动浏览等活动各自按开关启用。[记忆需求](requirements/long-term-memory.md)

### 语音消息与心情表达

收到语音后按真实转写接话，主人明确要求语音时合成并发回当前会话。语音确认送达后，以语音本身作为回复，不额外补发占位或文字确认；主人同时要求文字时提供对应内容，其他业务结果仍按实际需要说明。自动语音使用 15% 的基础概率和当前心情倍率，最长 80 字，明确的文字要求优先。生成失败或发送未确认时保留可读文字。文字、语音和自动配图共享心情。新实例首次启用语音时默认使用鲸鱼娘音色，日常语音和实时通话共用当前音色。音色属于伙伴的统一表达偏好，只通过ClawChat或已关联QQ的主人私聊管理：询问可选音色、按“小鲸娘1”“大鲸娘1”这样的昵称切换或恢复默认，由鲸鱼娘介绍声音特点、按实际结果回复，不要求用户记住后台音色原名或ID。通话页读取已保存的选择。候选目录随鲸栖更新，每个实例独立保存，切换经真实合成核实后生效，失败保留原选择；通话开始时固定音色，聊天中修改用于后续语音消息和下一次通话。歌曲演唱预设独立。[心情需求](requirements/mood.md) · [语音需求](requirements/voice.md)

### 表情包

QQ 和 ClawChat 共用一份表情库和选图规则，图片发回当前聊天。手动发图按用户请求处理。点名要表情时直接按名称、标签或编号查图库，找到就发，找不到就说明。已明确引用的图片从当前会话取材，明确请伙伴画图时走生图。用途不清楚时用一句话确认。关闭自动表情后仍可手动请求。

预装100张已审定素材及其标签，素材原件作为产品资源保存，实例使用一份可编辑图库。首次使用与完整重置导入预置资源；日常重启或更新保留用户新增、修改和删除的结果。图库补全时保留已有图片和使用记录。

**入库时标注图片用途。** 每张素材可标记场景、具体话题和表达方向。例如「举白饭」对应熟人玩笑、白饭、蹭饭、自嘲和大肥鱼自己。收录的素材只要用途确认并允许自动使用，就可以在匹配的对话中参与选图。主人可在收录时说明用途，也可事后通过聊天补标或设为只手动使用。用途未确认的图片先供手动使用。主人可在 QQ 私聊明确导入已登录机器人账号的收藏，按图片内容去重，并保留已入库素材的名称、标签和使用权限。个人 QQ 收藏可先发给伙伴，再明确要求收录。

**普通聊天按以下顺序尝试自动配图。**

1. 检查本轮资格。收到用户消息并准备正常回复时，自动表情已开启且概率大于零，才进入抽取。普通查询、搜索和读取资料仍参与自动配图。明确要求发图、只发文字、收录图片或执行写入操作时，走对应处理。QQ 群先满足原群回复条件，后台活动和实时通话使用各自流程。
2. 一轮只抽一次。基础概率默认 50%，乘以抽取时的心情倍率，最高 100%。抽中才进入配图判断和图库查询。
3. 复用这一轮生成正文的模型调用，输出内部结果「跳过」或图片的场景、具体话题、表达方向。明确跳过、格式无效或多个结果时只发正文。完全漏写时，只有用户原话和实际回复指向同一具体用途并能唯一定位合适素材，才补配图。认真倾诉、否定、引用转述或语境不明时保留正文。用户看到正文和实际送达的图片。
4. 仅从场景和主要话题匹配、表达方向相容、允许自动使用且文件可发送的素材中选一张。多张匹配时，先比较补充话题和表达方向，再按当前聊天最久没用过的轮换。旧有只标场景的素材可用于明确选择的通用用途。图库没有合适素材就正常回复。
5. 发送前按本轮实际动作复核。已确认的只读工具成功后，沿用本轮已抽取的结果继续选图，不重复抽取；不能仅因调用工具而取消。实际发送媒体、写入操作、工具出错或未确认用途的工具仍取消额外配图，账号及更新管理保持原专用反馈流程。正常回复确认送达后，才在同一聊天发送至多一张表情。

emoji、颜文字属于正文的口吻。图片或 GIF 表情包由共同图库处理。[功能需求](requirements/stickers.md) · [体验验收](tasks/feature-experience-review.md#1-表情包)

### 探索、分享与私人日记

B 站是首项兴趣活动。用户可以搜索、发链接、看字幕或评论、追问视频内容。总结说明实际取得的资料，并可把有来源的浏览内容保存为经历。两端使用同一份 B 站账号状态及经历。登录后的评论、私信、点赞、收藏和动态沿用各自权限，收件箱提醒和自动浏览按各自开关启用。[B 站需求](requirements/bili.md)

主动联系依据获准记忆、目标会话和真实经历组织内容。新实例默认开启，主人可设置或暂停。遵守联系时段、空闲条件、冷却时间、每日次数及共同后台额度。[主动联系需求](requirements/active-contact.md)

日记的自动取材限于真实活动和相应感想。日记默认保存为私人档案，可查看、修订和删除。主人可以明确选择发 ClawChat 动态或 QQ 空间，发布前核对正文、受众和权限。[日记需求](requirements/diary.md)

### 创作与作品

用户明确请求时生成图片或修改参考图，默认一次一张。作品保存后回到发起会话。[图像需求](requirements/image-generation.md)

主人可在聊天里说「写歌」，接着提供主题或歌词。也可以直接发「写歌：海边的夏夜」。ClawChat 的「鲸栖歌曲」复用 SongSmith 首页。创作支持文字问答、哼唱和手绘旋律，主人在原私聊确认草稿后生成。生成结果回发起会话，并保存到两端共用的作品库。「我的歌」提供任务进度、多版本、封面、逐句精修、播放及下载。「发现」展示主人主动分享的版本，获邀好友可听歌、点赞和评论。主人可在后台查看作品统计、受邀听众和管理评论开关。首次开通保持私有。「歌词精校」在配置对齐服务后由主人主动开启。歌声沿用平台的演唱预设，日常说话音色由语音设置管理。[唱歌需求](requirements/singing.md)

### 实时通话

主人可在 ClawChat 原私聊说「我们打个电话」，收到私有「鲸栖通话」卡片，点击后在通话页发起呼叫。通话页使用当前 Agent 的头像和昵称，提供呼叫、挂断、静音、字幕和开口打断。常用设置可调整打断、麦克风和字幕体验。通话和语音消息读取同一份说话音色设置。[通话界面](tasks/realtime-call.md#深海通话界面) · [声音验收](tasks/feature-experience-review.md#7-实时通话)

先保障接通和首声。可提前的会话准备在接通时完成，用户说完后使用当前可用上下文尽快回复，历史整理可以随后完成。

通话和文字共用发起通话的 ClawChat 主人私聊会话，沿用同样的工具权限和记忆规则。每轮通话在会话历史中标记为「实时通话」。被打断时记录实际播放到哪里，供后续继续聊天参考。转写、字幕、普通通话答复和工具进度在通话界面呈现，私聊显示实际发送到私聊的消息。挂断后回到原私聊，可以接着谈通话里提过的事。[通话历史与首声](tasks/realtime-call.md#共享会话的首声延迟)

## ClawChat 与 QQ 的关系

一个伙伴可开通 ClawChat 和 QQ。明确关联主人账号后，两端共用人格、心情、获准记忆和业务档案。聊天全文、即时附件和工具上下文保存在各自的私聊或群聊会话中。私聊记忆和管理权限按经过验证的身份与来源使用。[双端会话决策](adr/0002-cross-channel-conversations.md)

普通回复及手动操作结果回到发起会话，明确指定目标的任务按用户的约定发送。主动问候、自动分享、B 站提醒和日记通知共用一份首选接收平台，默认 ClawChat。首次关联 QQ 时引导选择一次，之后主人可在任一已关联私聊修改。每次主动投递只发到选定位置，断线时保留原目标和回执。[投递需求](requirements/proactive-delivery.md)

同一活动只执行一次，按实际投递保存回执。私人档案独立保存，平台发布按明确确认的通道和受众处理。

## 平台能力与实例生命周期

首发以 2 GiB 云实例为目标规格，DSH、ClawChat 连接器和 QQ 网关可在同一实例运行。连接身份沿原绑定续期和恢复，回到原会话。资源吃紧时优先保障正在进行的聊天和连接，可延后的后台任务按实例限制等待。[实例运行状态](STATUS.md)

首发实例预装并启用写歌、歌曲作品页和 ClawChat 实时通话。使用新配对码开通后，可从现有聊天入口发起这两项功能。[预装与验收](DEVELOPMENT.md#首次开通)

ASR、TTS、生图和写歌沿用平台后端。每项扩展先核实平台支持、接口、权限、格式、额度及费用，再确认接入和验收范围。[平台能力核验](MIGRATION.md#已确认前提先核实平台能力)

鲸栖发布带版本、完整性校验和宿主兼容条件的 `.connect-plugin` 安装包。更新和回退保留用户选择的人格、原会话、记忆、账号、作品以及发送和生成记录。任务结果未确认时继续查询原请求。前台资源费用及模型用量由平台计量，后台请求受实例的开关和共同额度控制。[更新策略](tasks/plugin-updates.md)
