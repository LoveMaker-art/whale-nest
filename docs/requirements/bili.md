# B站功能需求

已确认功能需求；对应[技术设计](../technical/bili.md)。实际部署、启用与验收以[STATUS](../STATUS.md)为准。

## 1 账号和经历共用

一个伙伴实例维护一份B站登录状态、账号操作状态和浏览经历。已关联的QQ、ClawChat主人私聊使用同一份，不按IM平台重复登录或复制浏览历史。账号身份与平台主人关联需核实，不按昵称合并。

经历只记录实际取得的内容、来源、时间和完成状态，供后续查询及[日记](diary.md)使用；两端原聊天记录和即时工具上下文仍分别保存。

## 2 用户体验和保留范围

| 场景 | 需求 |
| --- | --- |
| 找内容 | 按兴趣搜索，或接受指定视频链接；保留当前筛选条件和设置，不因收敛重置。 |
| 阅读和讨论 | 基于实际取得的标题、简介、字幕、评论等总结并支持追问；缺失资料明确说明，不用读到标题冒充完整观看或画面分析。 |
| 手动请求 | 在QQ或ClawChat都可请求，默认回复发起会话；明确指定其他获准目标时遵循统一投递规则。 |
| 经历回看 | 同一份获准浏览经历可由主人从两端查询，不另维护两套活动记录。 |
| 自动浏览与提醒 | 各自显式开启；未指定目标的分享、评论/私信等消息提醒继承[全局首选平台](proactive-delivery.md)，不重复询问接收位置。 |
| 登录后的操作 | 保留评论、回复、私信、点赞/投币/收藏、B站动态及其他已确认功能；依各项实际权限、登录条件和账号限额执行，不因改用原模块删减已有补充能力。 |

B站站内评论、私信和动态是对B站对象的操作，与向QQ/ClawChat通知是不同动作；全局接收平台不改变站内操作对象，也不授权自动互动。

## 3 开关和复用

默认保持当前自动浏览及账号监控开关状态，后台自动评论、私信或发布不因本次设计开启。首轮自动兴趣活动沿用每天最多一轮、先读一个视频的既定范围；分享和实际后台模型请求受共同频率及额度限制。手动请求与自动活动区分计量，不要求前台查询等待主动联系冷却。

以原bili模块为主体收敛业务，保留现有搜索、登录、私信、动态、三连、筛选和消息监控等补充能力。适配到同一个账号与执行入口，不另并装旧独立B站插件，不按两个IM分别实现业务。原模块缺少的补充能力不假装已经原生提供，具体接线在技术设计中列明。

已有经历、账号凭据、限额、通知记录及不确定回执保留；同一操作不因换平台重新执行。真实B站账号验收继续按用户此前决定保留为非阻断项，不能以模拟成功冒充登录账号已实测。

## 4 验收重点

1. 两端读取同一账号状态和同一份获准经历；切换IM不重新登录、清空状态或重做已执行的账号操作。
2. 手动请求返回原会话，自动分享及已接入的提醒读取同一个全局首选；不自动双发。
3. 总结能对应实际取得的资料；缺失字幕、评论或画面能力时如实反馈，失败不记作成功活动。
4. 旧功能、筛选、限额和回执保留；普通主动搭话与B站自动浏览分别启停，不互相隐式开启。

当前采用的原模块与自写补充分别见[实现清单](../IMPLEMENTATION-INVENTORY.md)，当前可用及真实验收范围见[STATUS](../STATUS.md)。
