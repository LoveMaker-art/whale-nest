# ClawChat Connect：无侵入集成所需的通用契约

日期：2026-11-25。核查基线：官方集成包 `0.2.23`、源码 `adfec616c51f61ee6cccf8ce08dd99b80c825c50`，Core/CLI/Skills 版本 `0.1.0-beta.9`。本报告不声称该版本是阅读时的最新版本。

## 先看这里：这份文档要解决什么

目标是让鲸栖完整使用ClawChat的消息与会话能力，同时使用原版官方连接器，后续更新走官方渠道。通话、歌曲、选表情等业务由鲸栖自己维护；平台提供任何插件都能使用的正式接入入口。

这里的“接口”就是插件调用平台能力的正规入口。官方内部已有一项能力，和第三方插件能通过完整、受支持的入口使用它，是两件需要分别核对的事。当前我们为下面四种接入改过连接器；文档要求补齐通用入口，再移除这些扩展。

| 当前耦合影响什么 | 平台入口需要让插件做到什么 | 后文对应 |
| --- | --- | --- |
| 图片、语音、歌曲和文件发回聊天 | 在对话中发送附件；耗时任务完成后仍能发回原聊天；拿到真实发送结果，断线后能核对原请求，避免重复发送。 | G2、G3 |
| 发动态前核对权限 | 通过官方入口查询当前账号能做什么、允许的范围；插件据此决定自己的业务操作。 | G1、G4 |
| 实时通话接着原私聊聊 | 让通话入口在原聊天上下文中执行操作，和打字协调先后；挂断、切换聊天或更新时正确结束旧操作。 | G5 |
| 正文送达后再补表情 | 让插件知道普通文字是否已发送成功，按顺序检查是否继续补图，再取得图片自己的结果。选哪张图仍由鲸栖决定。 | G3，也使用G2 |

四项功能之外，还要处理安装、查询状态、启动和更新。目前部分代码直接读取官方内部记录和目录。官方已有的管理入口先由鲸栖适配；确有缺口的部分再由平台补齐。后文G1、G6、G7列出这一层的要求。

因此，完整解耦包含两边的工作：平台提供并明确支持上述通用入口，鲸栖把现有接法迁过去，最后用原版官方连接器验证功能、历史任务和独立更新。后面的G1～G7是给开发者检查细节的清单，不是七个新业务功能；四个功能名称有了接口，也仍须完成安装和迁移这部分工作。

以下保留开发者需要的授权、顺序、失败恢复与验收条件。

## 1. 目的与结论

目标是让扩展应用通过受支持接口接入 ClawChat，保留消息、异步产物、权限核验和同会话交互能力，同时退出 Core 补丁、私有数据库/安装记录访问及定制宿主启动。

**本文定义完成该目标所需的完整语义条件，不再只罗列能力名称。**平台提供下列契约，集成方依照对应流程完成改造与验收，即有路径移除本次已识别的全部定制接入。仅提供同名接口、忽略时机/授权/结果恢复等条件，不算满足契约。

这不是官方故障清单：无活跃回合时拒绝 send_file、保护凭据目录、限制 Client 支持范围，属于当前明确策略。新增受支持场景须由平台接受并设计授权。本文不要求公开原始 Session、nativeId、SQL 列、令牌，或提供表情/日记/通话专用接口。

职责分工：

- 平台拥有认证、绑定授权、实际投递、权威结果、会话选路/队列及安装生命周期。
- 集成方拥有业务产物、目标选择、数据、模型侧扩展、消息展示策略和迁移代码。
- 平台接口实现不等于集成方已改造完毕；完成标准是双方契约通过后，实际以原版官方 Core/宿主运行并独立升级成功。

## 2. 契约总表

“必须”均指**完整保留此次核查行为并退出定制接入的条件**，不表示平台已经承诺开发，也不表示未支持即为漏洞。字段/方法名由平台确定，允许用等价公共接口组合实现。

| 编号 | 通用契约 | 官方 0.2.23 已有基础 | 本次仍需明确/补齐 |
| --- | --- | --- | --- |
| G1 | 获授权绑定身份与鲜活运行状态 | dsh 状态命令、绑定信息、激活流程 | 指定绑定的授权上下文及与本次激活关联的身份/就绪语义 |
| G2 | 受控媒体投递及产物交接 | send_file、上传、ACK、工作区策略 | 回合内可等待结果、受限异步授权、实际内容保证及所需类型/元数据语义 |
| G3 | 原操作/输出结果及历史恢复 | 工具请求记录、内部消息 ACK | 调用方可取得的稳定关联、只读结果查询、普通回复结果、旧请求恢复 |
| G4 | 当前身份只读权限快照 | 现有权限 HTTP 端点 | 不暴露凭据的受支持读取入口及字段语义 |
| G5 | 通用会话操作调度 | Session、Client turn、队列、取消 | 第三方调用资格、无假输入的准备、Runtime 声明操作、流式结果与生命周期 |
| G6 | 插件与绑定的公共管理 | plugin list/install/replace/configure/select、agent add、Bootstrap | 明确支持入口及稳定字段；已有绑定迁移方式须分别验证 |
| G7 | 原版宿主/集成升级与兼容边界 | 官方签名更新器、宿主、SDK、Exposure | 通过受支持入口发现/准备/切换/恢复；明确公共 factory/协议及发布资源生命周期 |

G1/G3/G5 可复用同一权威状态；G2/G3 共用现有工具/消息账本。无需为各类业务建立平行状态系统。G6/G7 已有能力优先由集成方适配，只有具体不足被证明后才新增。

## 3. G1：绑定身份、授权范围与就绪

接口须让获授权调用方取得当前绑定的 Agent、实际授权主体、目标会话范围以及当前运行状态。身份/就绪必须能关联到**本次有效激活**，不能把上一次绑定的 connected 当作新身份已就绪。

平台可返回不透明的授权范围/修订标识和有效状态，不必公开 installation_owner、activation 时间、token 非空检查或数据库路径。解绑、重新绑定及插件换代后，旧调用上下文的有效性由平台核验；旧操作结果仍按原归属查询。

身份、插件换代及连接新鲜度须分开：持久绑定身份/修订在账号或目标变化时改变；插件激活代际用于拒绝旧插件；宿主/连接 epoch 用于本次 ready。正常重启不能仅因 epoch 改变就使同一身份的所有持久任务失去归属。历史结果查询仍受当前授权约束，不因保留旧请求而授权给新身份。

这用于任意多绑定应用的初始化、身份切换和状态展示，不要求平台实现某个产品的“主人私聊”业务判断。调用方按公开授权范围选择目标，不自行推断其他绑定的归属。

**关闭条件：**首次安装、已有绑定、非固定 dsh 绑定、身份切换均能完成核验；直接打开官方激活/状态数据库的路径可以删除。现有状态命令若扩展即可满足，应复用，不另造身份系统。

## 4. G2：媒体与产物的通用投递

### 4.1 调用时机和授权

必须支持两个互补时机：

1. **活动回合内提交并等待媒体结果。**调用不能被强制拖到 Runtime 输出迭代结束后，否则“先取得媒体结果，再决定最终文字”会形成等待或丢失行为。
2. **原回合结束后的授权任务交付。**授权与提交方、绑定、目标和任务关联，具有明确有效范围及撤销规则，不借用另一活跃回合，也不信任模型自报的旧 turnId。

可使用官方任务、有限能力句柄或宿主端口。当前无活跃回合拒绝策略不应直接放开；必须先有可信来源机制。投递操作不能因调用方仍持有会话队列而等待同一回合结束，形成重入死锁。

### 4.2 产物内容、类型和元数据

支持批准目录、内容流或不可变 artifact 均可，但必须保证实际上传字节与调用方交接的产物一致。可用执行端 expected digest 校验或等价不可变内容保证；仅在调用方预哈希路径不够。不能为下游数据目录解除凭据保护。

媒体应支持现有 image/GIF、audio、video、file，保留 caption、文件名和原有 as_document 能力。调用方能够约束允许的最终类型，并取得实际类型/MIME。音频作为文件交付等转换需要可表达、可核验，不伪造为音频 ACK。

时长、尺寸可由平台可靠探测，也可接收经校验的属性；需要的是最终媒体结果等价，不是保留某个第三方旧字段名。类型不符或内容摘要不符时，应在发送前拒绝。

### 4.3 操作结果

提交使用稳定操作关联；相同关联重复请求不产生第二次发送，参数冲突有明确结果。接受/失败/未知以 G3 的官方结果为准；调用方 abort 不等于平台确定未接受。

**关闭条件：**活动回合内、回合结束后、并发任务、类型转换、内容替换及响应丢失均可按同一通用投递体系处理，第三方媒体工具补丁和自行认证发送路径可以删除。

## 5. G3：可取得的真实结果与历史请求恢复

### 5.1 新操作和普通 Runtime 输出

调用方必须能拿到可查询的稳定操作引用。普通 Runtime 回复若没有直接提交返回值，需通过公开输出关联或结果事件让其作者取回操作引用；仅生成一个作者拿不到的 operationId 不构成闭环。

产生外部效果前必须已有可恢复的提交关联：使用提交前已知的稳定引用，或允许按调用方持久幂等键只读找回原operation。即使服务器生成的operationId返回丢失，也不能迫使调用方换号重试。

结果至少能区分：待处理、平台接受、明确失败/拒绝、已提交但结果未知，以及未发送的取消/抑制。现有状态名可继续使用，但必须有准确含义。平台接受返回真实出站 messageId，仅代表接受，不表示已读或播放。

ACK 以**消息**为单位：两条消息分别有结果；一条图文消息的多个 fragment 不要求各有 ACK。普通输出继续遵守顺序、可见性、缓冲和 no-reply。生成结束、输入受理和 reply_sent 日志均不替代平台结果。

依赖后续消息仅在前条accepted且资格仍有效时提交。失败、unknown、取消或抑制时不自动继续；关闭或换代要阻止尚未交接的后续消息，已经交接的则保留实际结果，不能虚报撤回。

结果入口必须在输出迭代完成后仍可使用。事件或查询均可，需定义去重关联、保留期、not-found/过期及迟到结果含义。业务计数由调用方按稳定关联归并，平台不实现图库等业务。

### 5.2 结果后的受控继续执行

为保持需要发送前动态检查的后续动作，作者可声明一个通用结果处理步骤：正文accepted后，在原输出组的串行顺序和生命周期内处理结果，再决定是否提交后续操作。可用标准结果处理器、依赖步骤或等价机制实现；不固化业务回调名称，也不向作者交出Core对象。

处理步骤关联原输出/提交与有效插件代际，具有取消与截止条件。作者在真正提交后续媒体前复核自己的动态资格；G2发送使用该组允许的能力或独立投递worker，不能重新排入自己仍占用的会话队列。后续结果归并后结束原组，再放行下一同会话任务。

组已结束、超时、关闭或换代后，迟到结果只更新原操作状态，不能重新触发外部动作。若平台只提供无顺序约束的异步通知，需要补上等价依赖执行语义，不能声称已满足本项。

后续步骤失败或取消不得重试已经accepted的前序消息；恢复按原步骤关联归并，不重放整组外部效果。这一要求可由轻量结果处理边界满足，不要求平台新建完整工作流引擎。

### 5.3 迁移前的历史操作

旧请求不能因接口或工具命名变化而再次执行。应有受支持的历史只读查询，或由官方提供可验证的原请求映射/导入。查询已存在记录不应依赖旧工具仍在现行目录中注册。

已确认的真实回执保留；未知只核对原权威请求。not-found/过期不能当作确定没发出的证据。调用方不向平台伪造“我认为成功”的回执。

若新操作可用、旧未知请求却失去原有查询恢复能力，只能称新路径完成迁移，不能称完整保留已有行为。

### 5.4 两个通用消费流程

- **顺序附加内容：**正文走普通输出；其accepted结果进入同组继续执行，作者复核动态资格后调用G2发送后续媒体，再按媒体自己的结果更新状态。平台只理解通用结果/依赖步骤，无须专属 after-reply 钩子。预排两条消息仅在能保持相同发送前检查、取消和组顺序时等价。
- **媒体优先回复：**作者生成媒体，经 G2 在当前回合内等待结果；确认后选择媒体说明文字，未知则保留原文字。之后正常结束 Runtime 输出。不能只提供“生成完成后的通知”。

源码独立验证已发现：MESSAGE_SEND 交给内存传输、无 ACK 后远端/本地关闭，真实客户端分别抛 TransportError/StateError，toolFailureState 均分类为 failed。此结果应结合 failed 的正式定义审核；不能把所有同类异常一律改 unknown。本次未证明服务端接受或持久 worker 完整落盘。

**关闭条件：**新/旧操作、普通回复及媒体的结果关联可取得；故障、重启和迟到结果可按原操作恢复，第三方私库回执查询及专属正文回调可以退出。

## 6. G4：当前身份的只读权限快照

平台已有 GET /v1/agents/me/permissions。需要通过受支持的固定工具或受控宿主能力读取，不暴露令牌，不开放任意认证 HTTP。

读取须表达现有动作策略、受众和有效授权窗口及时间单位；失败、未知和缺省不默认为允许。读取不产生审批、权限变更或真实发布。具体“是否发布、发给谁”留在业务方，平台不内置产品受众规则。

原子条件发布不是替代现有 GET→POST 行为的前提，若新增应另行声明，不能混入本次必须项。

**关闭条件：**权限读取有公开入口，后续实际写操作仍使用现有官方工具；不再为读取权限修改工具目录或提取凭据。

## 7. G5：按会话执行 Runtime 声明操作

仅开放普通文本 submit/cancel 不能完整承接无输入准备、原子包住 Runtime 前后处理的交互。需要通用的会话操作语义；可扩展现有 Client/Runtime 接口，不要求另建会话系统。

### 7.1 权威定位与准备

获授权调用方按公开范围定位/准备当前逻辑会话，得到不透明 sessionRef 及选择修订/等价前置条件。空历史时可以准备 Runtime，不提交假用户消息、不调用模型来制造授权。当前选择变化可检测，旧引用不能默默落入新会话。

不要求公开 native thread ID、原始 Runtime Session 对象、Core registry 或可变 Binding。

### 7.2 同队列的声明操作

当前 Runtime provider 可以通过公开契约声明有限、带校验的会话操作；宿主按请求的 sessionRef、选择前置条件、操作标识和权限校验后，进入与普通文字相同的队列/生命周期，在必要时启动原 Runtime，再调用其声明的处理器。

平台负责路由、排队、受理、取消、关闭和旧代际失效；处理器在**其自己拥有的 Runtime 实现内部**处理前后准备及流式输出。不是让调用方上传任意代码执行，也不是向业务方借出 Core Session。

处理器须取得实际执行时确定的公共工作区/模型上下文；当前选择、身份及代际前置条件应在出队执行时再核验，不能只在提交时核验。

会话操作与G3共用提交关联及幂等语义：回执丢失后重复提交同一操作不能再运行一次模型，参数冲突应拒绝；重启后未知操作查询原结果，不自动重新执行处理器。

该能力适用于交互准备、受控工具操作和其他需要与聊天串行的入口。操作名称及业务负载由 provider 声明，不在平台硬编码语音或表情协议。

### 7.3 输出与取消

操作结果可以只返回获授权发起入口，不自动投递 ClawChat。需要发回聊天的内容另走普通输出/G2。原生历史由 Runtime 自身维护；可见私聊只展示实际对私聊输出的内容。

排队取消不执行处理器；运行取消由宿主与 Runtime 的公开取消协作，有明确终态。新建、切换、归档、关闭、插件替换时，旧操作不写入新目标。可支持 provider 选择模型，但不由平台实现业务模型策略。

取消当前操作不能作为另一项任务排到它后面等待；须有按原操作标识触达运行方的旁路控制，且旧取消不能伤及下一回合。队列包围实际 Session 操作/模型生成，不要求占住外部媒体播放的全部时长。

**关闭条件：**同一逻辑会话能够无假输入准备、跨入口串行操作、保持原线程、取消及关闭；完整过程不暴露私有句柄，也不需要共享通话专属扩展。

## 8. G6/G7：公开安装、绑定、启动与升级

### 8.1 优先适配已有管理入口

官方 plugin list/Core 插件查询已有版本、状态、完整性、代际及保留版本等信息；Bootstrap 有 bindingId、Runtime provider/capability 和 runtimeConfiguration。集成方先从这些公开输出替代配置与 lock 的读取，身份判断不再哈希数据库路径或整份私有配置。

绑定视图目前位于受支持 Client 范围内，部署工具/DSH 调用方取得等价视图的授权入口仍需确认。仅存在一个其无权调用的路由，不算满足本项；公开结果中的内部路径也不应重新成为依赖。

插件 install/replace/configure/select 及 agent add 提供管理基础。绑定参数变化应走宿主受支持的排空/换代事务；不能直接写 plugins.lock 的代际、保留版本或 runtime override。

插件列表与绑定视图的分别读取不天然形成原子快照。管理操作须在执行时核验期望身份、配置修订及插件代际，或由官方事务提供等价并发保护。`agent add` 会构建并整项替换绑定，不能直接当作保留已有模型/显示等设置的局部patch；只用于首装或经过完整设置继承验证的离线路线。

首次安装与已有配对实例必须分开验证。现 Client provider 切换入口对活跃绑定有限制，不能假设它能在线无损迁移所有已配对实例。平台需明确受支持的离线管理或保留激活的迁移流程；已有工具足够时由集成方重写安装器，不再提专属接口。

### 8.2 原版宿主与官方升级器

集成方通过公开启动、安装/运行快照及官方升级/回退接口工作，不解析私有 release/state/receipt 目录，不动态改官方 host.json 的 agent 入口，不生成在两个 Core 之间分流的启动 shim。

官方内部继续做签名、资产和状态兼容校验。若公开管理结果缺少迁移必须的信息，可增加通用候选准备/兼容结果；不要求公开内部安装目录结构。

SDK、公开 factory/bridge 协议及 Exposure 的兼容边界应明确。扩展可以自带原样依赖代码；固定依赖版本本身不等于修改官方连接器，但升级验证不能再要求重编官方 Core 或恢复旧启动器。

发布资源的保留/注销规则应由官方生命周期管理。扩展自己的进程、租约修复、准备和业务数据迁移由自己的受支持生命周期承担，不能继续依赖改写官方入口。

**关闭条件：**首装、已有实例迁移、同版本 replace、更新、回退和仅官方连接器升级均沿受支持入口完成；全过程没有手写私有 config/lock、宿主入口覆盖或第二套发送连接。

## 9. 完整性验收与交接判定

以下为完成本次无侵入集成的组合验收，不以某一个业务名称限定平台实现：

| 验收 | 可观察结果 |
| --- | --- |
| 绑定与首次启用 | 新/已有/非固定名称绑定均在当前授权身份下工作；旧状态不冒充新激活 |
| 媒体交付 | 回合内可等待、跨回合有授权；内容/类型/元数据与交接一致；不放开凭据目录 |
| 故障与恢复 | 明确拒绝、交接后断链、ACK 超时、迟到 ACK、重启和重复请求有正确原操作结果 |
| 历史迁移 | 已确认不重发，未知查旧权威请求，接口换名不制造第二次执行 |
| 普通输出 | 文字/图片按实际消息取得结果；不把生成结束或控制通知当 ACK |
| 权限 | 只读查询无写入、不泄露身份，实际动作复用官方授权 |
| 会话 | 无假输入准备、同队列、跨入口同历史、切换/取消/关闭/换代隔离 |
| 安装与回退 | 不手写私有安装结构，原身份、新增数据和不确定操作保留 |
| 静态与运行审计 | 原版官方 Core/宿主，无私库/lock读写、安装状态解析、分流启动器；生产/诊断/独立入口一起核对 |
| 独立升级 | 保持扩展包不变，仅更新兼容公共契约的官方连接器，功能、会话和托管入口恢复，无需重打 Core 补丁 |

**充分性结论：G1–G7 的语义全部满足，且集成方完成上述替代与组合验收后，可以移除本次已识别的全部侵入和私有状态依赖。**这不依赖 raw Session、nativeId、专属 after 回调或内部 SQL 字段。当前官方尚未提供并验收全部条件，不能把本契约当作已完成部署；但接下来应逐条实现/核对这些关闭条件，不再退回泛泛“可讨论接口”。
