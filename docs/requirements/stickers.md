# 表情包需求

本规格细化[表情包产品基线](../PRODUCT.md#表情包)。实际部署、启用与验收以[当前状态](../STATUS.md)为准。

## 1 用户体验

| 场景 | 需求 |
| --- | --- |
| 发送表情 | 说“发个开心的表情”，从已有图库匹配并发回当前会话；没有合适素材时如实说明，不用虚构文件或新生图代替。 |
| 普通聊天 | 遵循[产品基线的自动配图顺序](../PRODUCT.md#表情包)。主人可通过聊天开启、关闭或调整基础概率。抽中后结合本轮语境选择用途，发送前按实际动作复核，一轮至多自动发一张。 |
| 明确收录 | “把这张收为表情”才执行；素材来自当前会话中实际可取得的图片或明确引用。没有图或指代不清时先澄清。 |
| 整理图库 | 主人通过对话查看、命名、加标签、删除，按实际保存结果反馈。 |
| 两端使用 | 一份原stickers图库供已关联的QQ、ClawChat主人使用，不分别维护一套库。 |

主人明确收录后，图片成为获准共享素材；未收录的另一端会话图片不自动读取或搬入图库。收录不等于额外调用视觉模型自动命名，首轮使用主人提供的名称、标签或简单默认值；自动收图和看图起名作为保留能力，启用前另行核对。

## 2 入库用途与本轮配图

图库中的名称和描述性标签用于查找及自动匹配。自动候选须有已确认的场景标签并允许自动使用。已支持的场景包括庆祝、安慰、晚安、熟人玩笑、吃喝、问候、回应、感谢、陪伴、撒娇、情绪表达、惊讶、疲惫、思考、吐槽、休闲、音乐和节日。每张最多五个短标签，优先填场景、具体话题及表达方向。主人指定只手动使用时退出自动候选。重新导入同一图片保留已有名称、标签和自动使用权限。

抽中后按当前可用图库给模型场景词表。正文和隐藏结果同一次生成，结果为「跳过」或一组场景、主要话题、可选补充词和表达方向。方向为大肥鱼自己、给对方、一起或围观。例如「你这鱼又来蹭白饭了」接自嘲时优先举白饭，聊上班划水时选择摸鱼，用户需要鼓励时不与大肥鱼自己求哄混用。缺少主要话题或方向冲突时跳过。旧有仅标场景的图片仍可在模型明确选择「通用」时使用。

模型漏写标记时，仅使用同一轮用户原话和回复作保守匹配。一方单独提到关键词、候选不唯一、严肃话题或表达方向无法确认时，只发文字。明确跳过、无效标记和多标记均不进入兜底。

多个精确候选先比较补充话题和表达方向，同样贴合时按各自聊天的最近使用时间轮换。QQ 和 ClawChat 的流式与最终消息均只呈现正文及实际送达的附件。

## 3 复用与平台边界

继续使用同一个原stickers模块实例、图库读写、手动匹配和原心情效果。普通表达的开关和基础概率以同一实例设置为准，QQ、ClawChat分别适配收到的素材和实际图片/GIF发送，不复制图片管理或选择算法。

QQ收藏导入保留为QQ账号专属的显式操作，依赖已登录网关及权限；不因向共享图库添加图片就自动同步到QQ收藏。原功能保留与真实网关验收分别记录，不把共享图库可用当作QQ收藏已经接通。

删除影响共同图库，按原去重和文件管理规则执行，不自动撤回历史聊天里已经发出的图片。重启保留删除状态，不重新导入被主人删除的初始素材。

## 4 与其他功能的关系

手动发送和普通回复表情回到发起会话，不被全局主动消息首选改道。后台通知是否附表情按各自需求确认，本项不自动扩大当前后台媒体范围。

本项处理现成图片和GIF；生图、改图分别核对平台能力、费用与目标，不能把“收为表情”变成未经要求的图像生成。

## 5 验收重点

1. 未经主人明确要求不收录；明确收录后，两端查询与使用同一条素材，重复输入按原图库规则处理。
2. 按开关和本轮资格决定是否抽取，开关关闭、概率为零、抽不中的回合仅处理正常回复。抽中时核对实际模型请求次数，内部判断与正文同次生成。用有效、缺失和无效的结果验证 QQ 与 ClawChat 的流式和最终消息，确保内部标记不会出现在聊天框里。
3. 无匹配、素材不可发送、明确操作和手动已发时只交付本轮正常结果。同类不同话题与不同方向不会混发，同等匹配按当前聊天的使用顺序选择，修改和删除在重启后保留。
4. 另一端未收录的私聊图片不可自动作为本轮素材；其他参与者不能管理主人图库。
5. 每个平台分别取得真实发送结果；未知回执不换请求重发，QQ收藏及自动视觉命名不随本项默认启用。
