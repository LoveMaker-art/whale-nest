本轮已在 dev.19 完成可无损收敛的实现、受影响回归、源机部署及真实热更新验收：自有 Runtime/DSH Bridge、公开 factory/createBridge、模型配置、官方 Exposure、正常 `dsh` 身份查询、删除 Core `tool status`，以及更新/QQ 重载后的原 SDK 恢复。三个 App 资源保持两个可见入口，稳定原卡片与歌曲 URL 保留。[实施与验收](tasks/connector-convergence-023.md)

Runtime 恢复、QQ 零 configure 重载、fresh 操作归属与未知不重放、cancel/close 窗口已经实现并完成对应验收，不重复排为未来可收敛项。官方出现等价接口时再核对四类必要边界；早期候选见[历史审计](tasks/clawchat-connector-intrusion-audit.md)，当前事实以本轮任务与 STATUS 为准。

用户随后明确基础投递由平台解决，媒体阶段只实施已证明无损且尚未收敛的部分。复核确认快照、业务目标、幂等和业务回执已经在鲸栖；连前台普通文档也无法用预先哈希、只读权限或唯一文件名替代实际上传字节校验。本次没有新的可无损迁移运行代码，不重复开发现有自有能力，源机仍为 dev.19。

后续只在官方提供等价的来源授权、字节校验和回执能力后重新核对接入；不新增鲸栖基础投递补丁，不采用链接降级、假回合或借用授权。现有功能与附加作品页保持，不能把链接当作附件已送达。

用户进一步明确：目标仍是彻底解耦，不能把必需条件改成泛泛提案后丢失目标。[通用契约](technical/clawchat-connector-platform-handoff.md)用G1–G7规定足以替代的语义，不要求专属接口，也不把新增能力等同官方故障。[内部实施表](technical/clawchat-decoupling-plan.md)覆盖I01–I14，包括安装/回退直接写lock、独立Liveware读lock、私有安装状态和启动入口。按D1平台条件确认/实现、D2自身适配、D3测试机迁移、D4原版官方独立升级验收推进；当前交付止于D0源码覆盖/设计，未开始新功能实现或部署。

## 已确认前提：先核实平台能力

语音、图片、唱歌等每项扩展先核对：

1. 实际服务与支持能力，识别、生成和消息发送分别判断。
2. 接口、型号、鉴权、格式、文件限制、任务完成及错误处理。
3. 权限、当前额度、计费、并发和云端资源；目录列出型号不代表当前请求可用。
4. 与用户确认体验、范围和有界真实用量，再接线并分别验证真实处理、消息送达和客户端效果。

仅使用平台后端；未确认项保留依赖，不静默改用外部订阅或本地推理。模拟与真实结果分开记录，平台失败不继续盲目付费重试。新增能力及后端变更沿用此规则，已确认的陪伴需求保持。
