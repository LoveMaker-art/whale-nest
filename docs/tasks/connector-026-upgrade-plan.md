# 官方连接器 0.2.26：以用户体验为准的解耦与更新分析

日期：2026-11-27。状态：四项非通话适配已实现并在源机启用，本轮真实链路验收通过，通话按用户最新要求暂缓。官方发布物与证据见[0.2.26核查](../technical/clawchat-026-decoupling-audit.md)。

## 用户最新确认的判断标准

保留用户能感知的功能和使用体验，内部流程、状态记录和实现方式可以替换。通过官方支持的连接器工具、Runtime SDK 与管理入口组合实现，不再把旧补丁的方法名、提前创建线程或内部回调本身当作必须保留的功能。

媒体已明确接受两项调整：由鲸栖维护受控稳定副本，不再要求官方发送端核对鲸栖传入的摘要；已取得的真实回执保留，丢失或旧未知结果无法公开查询时继续保持未知，不自动重发，不继续读取官方数据库补齐它。

先完成全部耦合分析，再统一更新指定源机的官方连接器和鲸栖插件。源码先行测试；打包与公开发布仍需另行授权。尚未批准通话改用独立上下文、私聊刷通话字幕、取消实时打断或隐藏现有功能。

## 替代方案的完整性要求

用户要求方案提出时就覆盖可以预见的边界和新增问题，保持与变更规模相称，不等用户逐项指出后再补设计。每个替代项须同时说明：正常流程及用户效果、数据与文件归属、失败／超时／重启恢复、并发与取消、资源回收和容量控制、引入的代价，以及可观察的验收方法。接口存在或单个调用成功只证明局部可行。

当前方案必须按下表补齐后才能进入统一切换，不因已有替代思路就记为完整解决：

| 替代项 | 必须考虑的正常及边界处理 | 新问题与验收 |
| --- | --- | --- |
| 发送文件交接 | 已在允许目录且由鲸栖保证发送期间不覆盖的文件可直接使用；仅对目录不允许或可能变化的输入创建自有临时副本。副本与任务关联，发送方仍可能读取时不删除；结果未知与文件是否仍被使用分别判断 | 不能给每次发送留永久副本。需要可观察的读取／任务结束条件、并发引用保护、重启遗留回收和总量预算；只有时间过长不能证明可以删除。预算不足时先回收已安全结束的自有临时文件；仍不足则暂缓尚未提交的附件并说明状态，普通聊天继续，原作品与图库保留。未确定这些条件及预算前，文件回收方案不算定稿 |

保留期、临时文件预算及不能自动恢复的场景属于方案需要说明的条件，不可在代码里临时猜测。每项分开标记“接口路线已核对”“方案已完整”“代码完成”“回归通过”“实机通过”；本轮目前只完成路线核对及边界整理。

## 四类业务的替代路线

| 项目 | 官方入口与鲸栖自己的实现 | 用户体验及结论 |
| --- | --- | --- |
| 媒体 | 官方 `clawchat_send_file`、`clawchat_send_image`、`clawchat_send_voice`；鲸栖负责可信目标、工作区交接副本、稳定请求及本地真实回执 | 可以按已确认的方向迁移。图片、语音、歌曲和文件继续发回原会话；优先通过下述替代保护正常体验，无法安全恢复时才保留未知。普通工具没有返回最终类型时不虚报类型；保留当前实际播放／下载体验，不静默强制歌曲变成仅下载文件 |
| 权限 | 官方 `clawchat_get_permissions`；日记等业务保留自己的受众与发布判断 | 可以迁移。删除自有权限工具，实际发布／删除继续走官方工具；查询失败不默认为允许，不添加更改权限功能 |
| 自动表情 | “自有 Runtime 协调官方文字和图片工具”：普通输出使用公开 `deliveryDisposition: projection-only` 保留投影，由官方 `clawchat_send_message` 发送正文并取得确认，再由自有逻辑复核并调用官方图片工具 | 已核对接口组合有实际可行基础，不必提供专属 after 回调。保留正文和表情两条消息。独立工具 worker 不等待当前 prompt 结束，不需重新进入所占用的会话队列。尚需实现并验证无双发、文字格式／引用、取消、无回复和多消息顺序 |
| 实时通话 | 真实 ASR 作为官方 Client turn submission；使用官方队列和取消，自有 provider 管理语音模式、播放记录和流式结果 | 有实际可复用基础，不能再仅凭“没有声明 operation”判不可行。现有公开接入资格、空历史／`/new` 后定位原私聊、运行取消归属仍须闭合。没有将这些缺口假称已适配 |

## 媒体减少项的替代保护

内部保护不必逐项复制旧 Core 实现。以不增加重复发送、错误确认或用户操作为准，优先采用下列替代：

1. **文件交接。** 每个发送操作使用自有独立副本、排他创建和只读权限；保存后不覆盖，发送前核对内容，发送中及未知状态不清理该副本。原件编辑不影响它。能保护正常业务中的覆盖、并发及清理问题；不宣称它等于官方执行端按预期摘要校验，也不宣称只读权限能阻止同账号程序主动改权限。
2. **新操作的结果保存。** 调用方等待结束与后台实际发送分开；自有发送执行方及时持久化官方返回的真实消息编号。页面关闭或上层等待超时不直接丢弃仍在执行的原请求。插件／机器崩溃发生在平台接受与本地落盘之间时，仍需原官方记录帮助恢复。
3. **官方同编号复用。** 精确0.2.26的 `submitToolRequest` 使用 `ON CONFLICT(request_id) DO NOTHING`，相同绑定和工具取得已有记录，不重开已有请求。它可作为新官方工具操作的恢复候选，不能等同于纯只读查询：记录不存在时会新建任务。已结束且非 indeterminate 的记录还会按90天／最多10000条清理，旧自有工具名称也无法通过新官方目录查询。因此不能无条件自动复用；必须先闭合原记录保留与不会重复发送的条件，闭合前仍保留未知。旧未知请求、被清理记录及官方明确 indeterminate 不虚报恢复成功。
4. **附件类型。** 图片和日常语音优先使用有明确类型检查的官方专用工具。歌曲需要格式处理时可在鲸栖内完成，再交官方发送，须验收实际播放、时长、大小和质量；不能因为工具没有返回类型，就推断歌曲一定作为文件或一定可播放。分析阶段要求转换后验证真实格式；本轮实现已加入有界ffmpeg转换，原件保留，实际覆盖见下方实施记录。

因此，不能把“没有独立查询接口”扩大成“新操作完全没有恢复路线”，也不能把同编号再调用包装成保证无副作用的查询。以上为实施前的约束。随后四项已按用户授权实现并在源机启用，详见实施记录；未闭合的旧未知结果仍保持未知。

## 通话重新核对后的实际结论

已确认的可复用基础：Client submission 未普遍禁止 ClawChat 来源会话；能够提交到已知原会话时，实际进入与文字相同的 `chatId/sessionId` 队列；Client 路径的结果留在 Client 投影，不经普通 `sendReply` 再刷入私聊。语音转写是用户的真实输入，不能与制造授权的假回合混为一谈。提前预热 SDK、首句再建原生线程属于内部替代，不能单独当作功能缺失。

当前必须解决的具体接入问题：

1. **官方 Client 的合法启动与使用范围。** Core 的公开获取入口只取得官方 Connect Client；当前发布物只带 DSH Runtime 和 Exposure 包，Client 兼容清单使用精确 Runtime 引用。不能通过改官方清单、冒用其他 Runtime 身份或读取私有 facade 来接入鲸栖。
2. **定位／创建原私聊的空白会话。** 已启动 provider 可从公开上下文维护自己的会话映射；但首次只有空意图或 `/new` 尚未执行时，catalog 没有对应完整映射。Client 的新建会话使用独立的 `__connect_client_session__:<uuid>`，不能假定它就是原 ClawChat 私聊。选择“随便一个当前会话”或读取官方表不符合本次目标。
3. **取消必须属于原语音操作。** 实际运行取消接口按 Session 取消，路径里的 turnId 未被精确校验。可以审查由鲸栖持有可信操作关联、只取消自己的 provider 操作的替代；必须覆盖迟到取消、下一轮和文字排队，不能把“挂断”变成取消下一条文字。

这些问题不要求平台照搬旧的共享通话函数。能通过现有公开入口组合解决就由鲸栖完成；仍无公开入口的，才列为平台缺口。当前证据不足以宣称完整通话已经可以无侵入迁移。

### 表情方案为何不再依赖旧正文回调

准确发布物中，`OJ` 先识别 `projection-only` 并不产生外发动作，surface 则保留原 Activity 投影；该字段不是新造的私有标记。独立 `ToolWorker` 从官方工具账本领取任务并直接调用官方执行器，不进入正在等待它的 Session 队列。官方文字工具成功返回 `sent/chatId/messageId`，指定 `replyToMessageId` 时使用回复事件。因此自有 Runtime 可以协调这两个官方工具，并保留现有先正文、后动态复核补图的行为。

实现时不能只隐藏最后一句：需统一处理同回合 assistant/final/turn Activity，避免之前已投影的文本又被 Core 自动发送。原 `outputVisibility`、无回复、多消息、Markdown／提及／图片处理、引用、回合成功统计和历史均列为回归项。正文未知不发图，图片未知不重发正文；CLI 中止不代表已提交的工具撤回。图片确认后才更新实际使用记录。

这条路径改变的是鲸栖自己如何使用公开 Runtime 输出和工具，不替换官方发送函数、不补官方二进制，也不读取官方数据库。

## 更新实施顺序与完成标准

1. 固定经过核验的官方候选，完成各项公开入口与替代实现的本地回归。入口缺口先说明具体影响，不直接覆盖当前源机。
2. 准备匹配的自有源码候选和可回退配置，核对原账号、模型、工作区、任务与通话空闲，再在同一次切换更新官方及鲸栖。
3. 真实模型核对原私聊文字、图片／语音／文档、后台歌曲交付、表情无双发、文字→通话→文字连续性、打断／挂断、首次空白会话和 `/new`。
4. 验证两个 Liveware、原卡片、QQ、重启、未知不重发及只升级官方连接器后的恢复；静态及实际文件访问确认没有 Core 补丁、官方 SQL／lock 读取和入口覆盖。
5. 实机通过后汇报，再申请打包。当前授权不包含新发行或自动 GitHub 推送。

官方 0.2.26 对应完整 Core 源码目前公开不可取。若最终路线全部使用原版连接器，此事不必作为升级阻断；也不再为了保留旧补丁而坚持重建 Core。真正的前置条件是上表公开入口和用户体验验收能够成立。

初始分析阶段未操作运行实例；后续实施和回归见下节。原始记录保存在 `.whale-nest/verification/media-official-active.json` 指向的任务目录，以及 `.whale-nest/research/official-026-contracts.md` 的最新重评节。


## 本轮实施（2026-11-27）

用户最新要求先更新其他功能及插件版本，通话先放一边。因此当前交付范围为官方0.2.26及四项非通话适配，通话资料和入口保留，页面展示维护状态。

- 媒体采用官方图片／语音／文件工具，工作区副本限制128MiB／128份；确认或明确失败后回收，未知结果保留到执行进程已结束且期限届满。原作品不删除。
- 自有发送执行方持久化参数、请求、结果和真实messageId；调用方取消后仍可落盘。恢复只读本地回执，不将再次提交伪装成查询；旧未知不重发。SQLite事务锁处理跨进程并发及崩溃释放。
- 格式由真实内容判定；WAV时长按数据计算，必要时用有时限／大小限制的ffmpeg转换。歌曲允许原文件交给官方通用发送，不能凭通用回执虚报最终音频类型。
- 只在本轮确实选中待补表情时，自有Runtime用公开projection-only保留历史、移除自动外发副作用，调用官方正文工具，实际确认后再发图。普通回复继续走Core原发送路径；失败／未知／取消不补发，不需要旧的afterClawChatReply扩展。
- 日记权限查询使用官方clawchat_get_permissions。启动器选择公开clawchat-dsh serve及官方签名发布物；源码加载仅重定向鲸栖自己的外置模块。
