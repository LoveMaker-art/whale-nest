# 鲸栖彻底解耦：依赖覆盖、替代实现与退出验收

11月27日进展：本文件保留0.2.23严格无损阶段的退出条件与清单。用户随后允许内部替代并暂缓通话；0.2.26非通话源码已部署，当前范围、证据和发行包待验边界见[连续实施记录](../tasks/connector-026-upgrade-plan.md#非通话剩余收敛2026-11-27)及[STATUS](../STATUS.md)，不把下表旧依赖当作现行运行事实。

日期：2026-11-25。基线：鲸栖 dev.19、官方集成包 0.2.23、自有 Core .0.2.23.2。当前运行和部署状态以 [STATUS](../STATUS.md) 为准。本轮只有方案和源码覆盖分析，没有执行功能迁移或部署。

## 1. 明确目标与充分性结论

用户目标是：完整保留现有正常功能，通过通用、受支持的平台能力退出侵入式实现。既不要求平台照搬鲸栖专属接口，也不把必要能力删成泛泛提案后丢失解耦目标。

**平台交接的 G1–G7 契约若完整实现并通过下述替代与验收，可以覆盖本次源码审计识别的全部依赖，形成彻底解耦路径。**必要语义是关闭条件；不是说平台提供几个同名方法就够，也不是说尚未实现的接口已经实测成功。本文把“充分”限定为所列清单及语义条件，实际完成仍须实现和实机验收。

“彻底解耦”的实际判据：

1. 官方 Core、Runtime 宿主及 Exposure 原样运行，无鲸栖 Core 补丁、替代二进制或宿主入口覆盖。
2. 生产、安装、回退、独立 Liveware 和运维路径均不直接读写官方私有数据库、lock、安装状态结构；受支持的配置/管理契约正常使用。
3. 无专属 after-reply/shared-voice 接口、无官方 Session 私有字段、无令牌自发、无假回合/借用授权。
4. 原账号/原会话、正常功能、未知请求恢复、新增数据及稳定卡片保留。
5. 保持鲸栖包不变，仅升级兼容公共契约的官方连接器，验证无需重编 Core、重打补丁或恢复旧 launcher。

鲸栖自己的 Runtime Provider、Bridge、业务模块和 SDK 租约继续保留；用官方公开 SDK 实现自己的 provider 不属于侵入。无需为了“纯官方 Core”切回原版 DSH provider 而丢失鲸栖业务。

平台文档：[无侵入集成通用契约](clawchat-connector-platform-handoff.md)。G1–G7 是语义分组，可由更少的公开入口组合满足，平台不必新增七套系统。

## 3. 四项 Core 扩展的具体替代流程

### 3.1 媒体、歌曲及自动语音

1. 鲸栖照旧核验业务授权和目标，创建内容快照与稳定业务ID。
2. 通过G1/G2取得平台认可的绑定/任务资格，将实际bytes交给官方产物接口，保存artifact和operation关联。
3. 官方核验内容、允许类型和元数据，使用原连接发送。我们不提取令牌。
4. 自动语音在当前回合内等待结果：确认后才把展示文字改成“（语音回复）”；未知保留原文字，不另起合成/发送请求。
5. 歌曲在原回合结束后凭任务资格发送，不借其他活跃聊天；允许当前音频/文件交付形式，按实际结果显示。
6. CLI/网络返回丢失时只查原operation；旧请求按第5节迁移。

内容保证、允许类型和最终元数据是保留当前行为所需条件，不要求旧字段名。FLAC当前通过不限制expectedKind允许文件交付；新接口应明确允许的结果，不伪造为音频。

### 3.2 权限

G1确定当前授权身份；G4读取权限；鲸栖执行自己的受众、publish/delete和有效窗口判断；原官方create/delete工具执行实际动作。GET→POST并发窗口保留原真实边界，不把原子受众锁新增为本次前提。

### 3.3 通话：不用原始 Session 的通用实现

建议采用G5的公开会话操作扩展，不强迫平台采用以下方法名：

1. 通话入口向官方请求当前获授权逻辑Session及选择前置条件，空历史也能准备，不制造用户消息。
2. 当前鲸栖provider声明“准备”和“互动”两类操作。官方校验、排队并确保原Runtime已start，再调用当前provider处理器。
3. 处理器在自己的closure中使用自己持有的DSH bridge/thread：准备原线程；互动时执行自己的voiceMode、上一轮playback、prompt和finally关闭mode。nativeId由provider管理，并沿既有公开onRuntimeThreadId回调告知Core；不作为新增操作的公共返回，不让通话调用者读取或猜测。
4. 官方不理解语音负载，只提供同队列、作用域、选择条件和生命周期。互动流返回通话入口，不由Core重复投影私聊；实际私聊附件仍走G2。
5. 排队取消不执行；运行取消经公开取消协作；/new、切换、归档和插件换代使旧操作失效，晚到结果留在原操作。

运行取消必须按操作标识旁路触达，不能排在被取消任务之后；执行时再核对当前选择/身份。工作区/模型上下文由宿主在实际执行时提供。队列不覆盖整段外部播放时长，播放账本继续由鲸栖管理。

现有普通Client文本提交是基础，但不能单独替代空历史无输入prepare和串行包裹前后RPC。G5需满足这些语义，不能把“支持DSH”或“能提交文本”视为已闭合。

### 3.4 自动表情：移除专属 after 回调

确定采用的替代设计：鲸栖选图并保存业务计划，文字照旧走普通回复。其accepted结果进入G3通用的同组继续执行步骤；原输入/输出、插件代际及组生命周期仍有效时，鲸栖重新检查取消、开关和当前图库素材资格，再凭G2提交图片。先持久占位，图片accepted后更新一次使用和轮换；失败/未知不虚记。结果归并后释放原组，再放行下一同会话prompt。

这不是把afterClawChatReply改名保留为私有接口：平台提供所有作者都能使用的投递结果/依赖步骤，不识别表情；鲸栖的回调和业务RPC留在自己的provider。G2在该阶段不重排自己占用的Session队列；步骤可取消、有截止。组结束/关闭/换代后的迟到正文结果只归并，不能复活补图。

后图失败/取消不重发已确认正文，也不整组重放。平台需要的是轻量结果处理及顺序生命周期，不是为了保护鲸栖现有pending变量另造系统；pending的具体替换由鲸栖完成。

预排“文字＋图片”只有在平台同时提供等价动态发送前检查、取消及原组顺序时才是备选，不再将单纯顺序发送误判为等价。概率、图库和轮换均留在鲸栖；单条图文消息按整消息ACK，不强求每fragment ACK。

## 4. 非 Core 依赖的替代与现有入口

### 4.1 身份和首次就绪

官方激活已负责验证Agent/主体及安装授权关系；鲸栖不再重复查询内部JOIN。持久化三种不同信息：

| 语义 | 变化时机 | 用途 |
| --- | --- | --- |
| 绑定身份及修订 | 账号/目标身份变化 | 业务归属、持久任务和恢复 |
| 插件激活代际 | 安装/配置换代 | 拒绝旧插件写入、目标版本核验 |
| 宿主/连接epoch | 重启/重连 | 确认ready属于本次激活环境 |

正常重启不能因为epoch变化就判定主人换人；插件代际也不能冒充账号身份。首次头像/问候继续用稳定请求和G3恢复；查询/操作携带公开scope或等价前置条件，由Core在执行时核验。

当前0.2.23状态输出有IDs/connected，但没有证明具备完整scope/revision/epoch条件，因此不能标作已实现。

### 4.2 安装及绑定信息，不读私有结构

已有公开候选的字段对应：

| 旧读取 | 公开替代来源 | 鲸栖调整 |
| --- | --- | --- |
| lock.version/status/integrity/activationGeneration/retainedVersions | GET /core/v1/plugins / 官方plugin list | 查版及目标代际按公开条目核验，不解析lock路径 |
| config绑定provider/capability/configuration | Bootstrap的bindingId/runtimePluginId/runtimeCapabilityId/runtimeConfiguration | 校验具体公开字段或官方配置修订，不哈希整份config/dbPath |
| 安装动作与同版本替换 | 官方install/replace/configure/select | 将原脚本事务迁到Core管理，不直接写代际/保留版本 |
| 首装后配置Runtime绑定 | 官方agent add的验证/保存流程 | 仅首装或完整继承模型/显示等设置并验证的离线路线；它会整项替换，不能当局部patch |

Client provider切换接口明确拒绝某些活跃绑定，不能用它承诺已配对实例在线无损切换。纯官方Core仍可加载鲸栖provider；撤Core override不等于换掉自己的Runtime provider。具体在线/离线迁移须由官方支持路线和实机验收闭合。

Bootstrap属于Client支持范围，DSH/部署工具获授等价公共绑定视图的入口仍须确认；字段存在不等于当前调用方已可使用。G6把这一授权条件列为关闭条件，不允许回退到直接读config/lock。

列表和绑定视图不是天然的原子组合快照；操作前后通过期望身份、配置修订及代际或官方事务检测外部并发修改，不能在删除旧hash后把这一保护漏掉。

### 4.3 官方安装布局、启动与独立服务

切换前保存原配对、业务状态和原操作关联；排空原组合；通过官方管理移除定制可执行文件选择，启动原版官方Core。不得继续由serve-media导入私有host入口并改agent目标，也不再复制一套host/Core/Skills来分流命令。

`liveware-service.mjs`的独立启动也要退出lock/activeArtifact查找：改用自身安装的稳定服务入口、公开状态或官方托管生命周期。只改主更新器而保留独立入口读lock不算完成。

自己的DSH profile、SDK租约修复、业务初始化仍需放在自己的迁移/生命周期中；它们是鲸栖职责，不因删旧launcher而遗漏。官方状态/owner/usage命令及管理传输若继续使用，必须取得受支持契约或用公开替代。

## 5. 历史请求与数据迁移

本次必须保留的不只是新接口正常路径：

- 已确认媒体/表情/日记操作保留真实messageId/momentId及原归属，不重新执行。
- 未知媒体及首次操作继续查询原binding/旧工具/旧请求，或使用官方可信映射。旧工具从目录移除不应让历史只读查询变成重新提交。
- 旧请求不存在/过期时保留未知，不能自动认为没发出；若原查询恢复能力完全丢失，该项仍未通过。
- 新任务建立业务ID→平台operation映射，先占位再提交；响应丢失仍只读恢复。
- 若服务器operationId仅在响应中返回，须能按提交前已知的幂等关联找回；不能因响应丢失而建立不了映射。
- 身份变化的历史记录不授权给新用户；平台授权与鲸栖数据归属分别核验。
- 回退保留前向新增会话、作品、图库和未知结果，只恢复兼容写入方。

G3须定义历史保留/迁移的官方路线。不能通过永久留下一个旧Core/旧私库读适配器，来宣布已彻底解耦。

### 6.1 当前发布版提前具备升级引导能力

原dev.19只有单跳更新：custom目标需要更高官方基线或officialOnly时会在安装目标包前停止，不能靠未来最终包里的代码反向修复旧worker。该事实不表示普通插件更新通道消失。

本轮dev.20候选已实现updateProtocol 1：发行声明受限updatePath，当前更新器读取最终目标及每个精确桥接发行，验证同仓库不可变资产、摘要、通道、版本前进与数据schema后，将整条计划固化为一次主人确认任务。桥接发行按tag查询，不依赖最近30条列表；缺失、改动或不支持接续的桥不会安装。

父任务保留最终目标，各单跳有自己的原版本、连接器操作、ACK、激活和回退记录。当前helper只完成本跳，持久handoff并释放原全局租约；新安装目录中的helper重新取得租约后继续。每次执行及崩溃恢复都核对helper归属、原账号/会话及精确安装快照。中间步不虚报最终成功，最终失败可停留或回到已验收桥接版，不声称回到最初版本。

用户不需要手动按发布时间逐版安装：未来最终发行声明并固定兼容桥接步骤，当前发布版便能自动找到并安装对应更新组件。同一次确认只授权已展示的最终版本及各步连接器要求，不在中途重新追latest。metadata不能给出URL、命令、脚本或可执行路径；后续迁移实现只来自经校验并安装的同源插件代码。

具体退出定制Core/启动接线的迁移，仍需平台契约落地后在已验证桥接代码中完成。桥接代码必须先兼容原组合，待旧单跳完成才接管迁移，不能在激活时立即改接线使旧worker误判。custom安全门槛继续生效，最终条件没满足时不会强行切换。

今后交付用户的首个版本须包含这套引导能力；尚未安装它的历史测试包不会自动理解updatePath，需先沿普通兼容更新/已授权安装入口启用。这样无需等待平台接口即可交付当前耦合功能，同时提前解决未来迁移代码可达性和跳版本的问题。实现、当前部署与验收见STATUS和更新任务，本节不把未来纯官方迁移说成已经完成。
