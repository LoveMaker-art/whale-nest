# 已交付实例的插件更新

鲸栖在现有 ClawChat 或已关联 QQ 私聊提供检查、确认和查询。两端共用更新任务及安装状态。实际进度见[STATUS](../STATUS.md)。

## 已确认范围

本任务维护鲸栖插件的版本发布、检查更新、安装切换、数据迁移和回退。更新面向已安装鲸栖的实例，复用 ClawChat Connect 插件管理器。

插件更新应保留用户人格选择、聊天、记忆、心情、经历、作品、账号配置和投递记录。源码及依赖版本变化与用户持久数据分开处理，继续复用既有模块和平台设施。

## 独立插件与复用原则（已确认）

项目目标是吸收原插件的有效功能，形成支持ClawChat与QQ的鲸栖独立插件。插件身份、发行版本、更新元数据、发布包及更新源均属于鲸栖；用户实例仅接收本项目集成并验证后发布的代码，上游新版本作为维护输入，由本项目评估合入。

原更新能力按实际适用性复用：版本检查、缓存、稳定/测试频道选择和提示数据可吸收，版本比较须按本项目版本规则验证；检查源使用本项目元数据。原DSH桌面命令和面板入口改接当前容器/Connect支持的执行与交互方式，复用现有安装管理、数据分离和必要恢复能力。保留唯一更新流程，避免重复开发同一能力。

## 现有代码证据

- [构建器](../../scripts/build-distribution.mjs)可生成Linux x64 .connect-plugin运行包及distribution.json摘要；数据位于包外。
- [原机更新器](../../scripts/update-m2.mjs)已有预检、备份、迁移、切换、会话检查及失败回退，但依赖本地工程、原实例配置和私有Core构建目录，不能直接视为普通用户更新产品。
- 固定b540的Connect插件管理源码支持GitHub Release来源及plugin update/replace；update要求来源身份不变，本地包改GitHub来源需显式replace。指定预发布须带确切tag，未指定版本的GitHub解析只选择稳定版。以上来自固定源码，平台当前开放入口及实际行为尚未在线核实。
- 固定上游的[更新检查器](../../vendor/aurabot/src/core/update.js)根据传入package元数据读取仓库，检查main/beta版本、缓存6小时并返回命令/提示；[原客户端](../../vendor/aurabot/client/client.js)呈现结果。它可作为复用来源，本体安装由DSH负责，云端执行须适配。
- 当前业务仍使用定制 Core 的共享会话等接口。本轮实现更新协调，不迁移这些业务；目标需要更高底座或纯官方连接器而当前仍指向旧定制程序时，明确报告配套迁移要求，不直接替换并损坏功能。

## 版本兼容

鲸栖比较发行版各段，`dev.20` 排在 `dev.9` 之后，同一基础版本的正式版排在预发布版之后。用户已批准将测试机当前 `1.0.0-beta.4.dev.20` 按原号发布，本次覆盖此前拟定beta.5的安排。未来目标版本必须高于已安装版本；每次发行仍须经过测试机验收并取得用户批准。

聊天更新核对 Linux x64 目标、实例数据格式、主人归属与当前安装来源。历史 `core`、`coreCapabilities`、`dsh`、`dshVersions` 字段继续忽略，不调用 Core/DSH `--version` 或要求自定义能力清单；官方连接器前置要求使用单独的 `prerequisites` 字段，通过官方集成包状态和自有定制登记区分实际底座。安装成功还须核对原绑定与实际可用状态。

## 新确认的发布前要求：先更新官方连接器，再更新鲸栖

用户确认以本节替代“始终不检查连接器版本”的最终更新策略。本轮 dev.15 已实现并部署协调代码；本地 38 项及 Linux 37 项相关回归通过，实机部署与验收边界以 STATUS 为准。

首个正式交付用户的版本必须携带该协调能力。dev.14 不解释后续新增的连接器要求，不能只给未来发行增加版本字段，就认为已交付实例会自动执行官方升级。

### 更新顺序与责任

1. 从已校验的目标鲸栖发行元数据读取官方连接器兼容条件及升级目标。条件随目标发行维护，不将当前底座写死成长期白名单；不能仅因官方版本较新就拒绝。
2. 通过官方云端入口读取已选择版本、实际运行版本、就绪、连接和原身份。满足要求就跳过官方升级；只检查和后台提醒均不安装任何内容。
3. 向主人展示鲸栖目标、必要的官方连接器变更和短暂中断。确认整个任务后，在空闲条件下调用官方升级，沿用其发行源、签名、包验证和宿主兼容检查。
4. 持久保存官方任务编号与阶段，结束触发更新的对话，等待官方延后任务完成。进程重启后接续同一鲸栖任务；不能把 accepted、已下载、已选择或 pending_start 当成完成，也不能在未知结果时重复提交升级。
5. 重新核对实际运行的官方连接器满足目标要求、原绑定仍在线，并确认启动路径没有绕回固定的旧定制程序，再通过现有插件管理器更新鲸栖。
6. 核对鲸栖实际启用版本、原会话可用及数据保留，最后报告整个任务成功。官方升级失败则不开始鲸栖切换；官方成功而鲸栖失败时，按已验证的组合恢复，保留新数据与未知回执，不盲目恢复数据库或重复发送。

DSH 版本仍不作为鲸栖自行维护的更新限制。官方安装器自身验证真实宿主 ABI、平台和签名的规则继续生效；没有兼容官方发行包时报告具体前置条件，不伪造成功或下载另一来源绕过。

### 发布前验收

- 连接器已满足要求时只更新鲸栖；缺少要求的历史发行仍能按原流程检查与修复。
- 连接器不满足时，官方更新、实际运行核对、鲸栖更新严格按顺序执行；签名/宿主不兼容、官方失败或身份变化时，不继续切换鲸栖。
- 覆盖官方升级导致的进程重启、未知回执、重复确认、恢复接续、外部运维改变选版及鲸栖失败后的组合恢复，保留原会话、新数据和不确定业务回执。
- 用指定测试机验证准备发行的具体组合后，再申请发布。本轮已验收 dev.15 与现有定制底座组合；真实官方升级及业务迁移后的组合，留到后续版本另验，不以模拟结果冒充。

### 已实现的协调接口与边界

[官方更新适配](../../src/official-connector-update.mjs)只调用镜像提供的 `clawchat-dsh plugin status/check/upgrade/rollback`；鲸栖发行不能提供可执行文件、目录 URL 或信任密钥。`pluginUpdates.connectorExecutable` 仅允许实例配置中的绝对路径，默认 `/usr/local/bin/clawchat-dsh`。签名、真实宿主 ABI 及包校验由官方更新器执行。

`distribution.json` 的新增字段如下，最低版本与确切升级目标由每个发行声明；当前候选沿用已安装的 `0.2.20` 底座。

```json
{
  "prerequisites": {
    "clawchatIntegration": {
      "minimumVersion": "0.2.20",
      "upgradeVersion": "0.2.20"
    }
  }
}
```

满足最低版本时不重复更新或降级。后续纯官方发行可增加 `officialOnly: true`。缺少该新字段的历史发行沿用原流程。字段无效或包含任意执行指令会拒绝；历史 Core/DSH 兼容字段不重新生效。

确认任务持久保存 `connector-submitting`、`connector-updating`、`connector-rolling-back` 等阶段，以及原身份、选版和官方任务编号。丢失提交或回退回执时只核对原任务，不重复提交。官方未确认实际运行时不切鲸栖。鲸栖拒绝/启用失败时，仅在选版仍归本任务、原鲸栖已选回且官方保留点明确兼容时请求官方回退；不满足条件则保留不确定状态，不覆盖其他操作。明确失败的任务可经主人再次确认创建新尝试，保留旧回执。

当前定制接线原样保留；新要求不满足时给出 `migration-required`，不把“官方包已更新”误报成“实际定制连接器已更新”。业务解耦和定制启动迁移由后续版本完成。本轮不会自动将当前实例换成纯官方。官方真实成套升级/回退仍须在准备该迁移版本时验证，本轮跨进程及故障路径使用独立状态和模拟官方 CLI。

原始来源、源码回退基线、包摘要、相关回归和实机记录集中保存在 `.whale-nest/verification/connector-update-coordination-20261124/`。[更新回归](../../test/plugin-updates.test.mjs)覆盖顺序、前置失败、未知回执、外部变更和组合回退；[跨进程回归](../../test/official-connector-native.test.mjs)使用真实子进程调用模拟官方命令并接续同一持久任务。

## 已确认的云端聊天更新流程

主人在 ClawChat 或已关联 QQ 私聊可以说「检查更新」或「查看更新进度」。手动检查每次读取发行源，后台检查保留六小时缓存和失败退避。确认操作需输入提示里的完整 `确认更新 <版本号>`，也可以输入 `暂不更新 <版本号>`。后台在回合空闲后执行，结果回到确认更新的私聊。原人格、聊天、记忆、心情、作品和账号继续沿用各自的数据目录。

| 编号 | 需求与验收行为 |
| --- | --- |
| U1 自有发行 | 沿用whalenest.runtime.deepseek-harness身份，从鲸栖自己的发布源读取确切版本、更新摘要和兼容条件；Linux x64包的tag与包内版本一致，发布资产有Connect要求的GitHub sha256 digest。上游变化先由本项目集成验证。 |
| U2 检查和提醒 | SDK 运行时复用六小时检查缓存。后台提醒使用全局首选私聊，同版去重，沿用当前人格和后台模型额度生成提示。额度不足或模型失败时使用简短兜底。支持仅正式版和接收预发布，默认跟随当前安装版本。 |
| U3 主人确认 | 提示当前版、目标版、更新内容及短暂中断；只接受可信主人私聊确认该目标版本，允许暂不更新。QQ与ClawChat指向同一实例，同一更新仅执行一次；普通好友和群聊不能发起管理操作。 |
| U4 后台执行 | 对话将确认写入实例数据目录。独立 Node 进程核对原绑定、兼容条件、空闲及旧版本完整性，调用实例内 Connect 完成切换。 |
| U5 保留数据 | 保留身份、人格、聊天、记忆、心情、作品、账号设置和投递记录。首版沿用数据格式 1，跨格式升级需要另行验收迁移与回退方法。 |
| U6 结果与恢复 | 以 Connect 安装状态与原绑定状态核对结果。目标版本启用异常时选择记录的旧版，保留升级后的数据。回执不明确时核对原任务，主动终态回执可由独立进程使用简短兜底发送。 |
| U7 官方连接器前置协调 | 按目标发行要求核对实际底座；需要时先通过官方渠道更新，确认运行和原身份后再更新鲸栖。检查和提醒不安装；当前业务迁移不在本轮范围内。 |
| U8 接续与组合恢复 | 持久保存官方任务，重启后不重复提交；只恢复本任务拥有且明确兼容的组合。当前固定定制程序不满足新要求时明确提示迁移，不擅自清理。 |

安装复用一个Connect管理器：旧本地来源迁移到鲸栖GitHub仓库时首次显式replace，后续同源update，预发布指定确切tag。Connect保留旧包可供select，但提交后的激活失败可能标记不可用，完整恢复仍需本项目现有步骤配合。

## 发行与实例配置

管理员在实例 `instance.json` 配置 `pluginUpdates.repository`，当前公开发行源为 `LoveMaker-art/whale-nest`。`channel` 可选 `stable` 或 `beta`。历史 `dshExecutable` 字段不参与查版和更新。用户通过既有私聊接收或查询，账号绑定由宿主及网关提供。

每个发行使用与包版本匹配的 GitHub 不可变 Release。资产放同版 `distribution.json` 和一个 Linux x64 `.connect-plugin`，两者都使用 GitHub 返回的 SHA-256 摘要。构建命令可用第四个参数传入纯文本更新说明文件。启用不可变发行并校验 tag 和摘要后再作为更新源。当前固定的 Connect 解析器按发行选取插件资产，因此首版每个发行只放一个插件包。[GitHub 不可变发行](https://docs.github.com/en/code-security/concepts/supply-chain-security/immutable-releases) · [GitHub Releases API](https://docs.github.com/en/rest/releases/releases?apiVersion=latest)

## 发布前提前实现：升级路径与新版执行者接续

用户要求现在解决未来更新入口，而不是等平台接口落地后再要求旧用户手工装过渡版。本轮dev.20实现通用updateProtocol 1，不改官方Core、业务功能或当前定制接线。发行schema仍为1，增加以下可选路径（版本和摘要仅为形状示例，实际必须是已验证的不可变发行）：

```json
{
  "updateProtocol": 1,
  "updatePath": {
    "schema": 1,
    "steps": [
      {"version": "1.0.0-beta.6", "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"}
    ]
  }
}
```

最终版本须高于全部steps；步骤最多8个、严格递增、同仓库/插件/平台，逐步声明并内置协议1。最终目标和桥接metadata都沿GitHub不可变发行、官方资产来源和digest核验。路径不得含任意URL、执行命令、helper路径或配置。桥接按精确tag查询，不依赖最近30条发行列表。stable不偷偷安装beta桥，缺失/摘要改变/环路/不声明的嵌套步骤均拒绝。没有路径的旧发行和在途单跳任务保持原流程。
