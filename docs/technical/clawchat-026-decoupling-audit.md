## 结论

**0.2.26 还不能支持鲸栖完整解耦。**权限查询已有可替代入口，媒体的后台发送限制已有实质改进；原私聊会话操作、普通回复的送达结果及同组后续执行仍有缺口。不能直接删除现有四类扩展并换用原版连接器。

这里分别判断官方接口是否足够、鲸栖是否已迁移。即使接口已足够，也需要修改鲸栖自己的调用并验收，升级连接器本身不会自动完成迁移。

| 图片、语音、歌曲和文件投递 | `clawchat_send_file` 明确允许后台、回合结束后、并发聊天和直接 CLI 调用；另有图片、语音专用工具 | 部分满足。原来“没有活跃回合就无法交付”的限制已解除；完整的产物一致性、最终类型确认及旧未知请求只读恢复尚不足以等价替换现有路径 |

## 接口证据与仍缺的语义

### 权限

包内 `skills/clawchat-core/references/tools.md` 第 1086 行列出 `clawchat_get_permissions`；`SKILL.md` 第 140 行明确策略、`moment.visibility` 和 `permission_windows`，到期时间为 Unix 毫秒。失败时不推断允许；实际写操作仍由服务端授权。

Core 发行二进制偏移 103964167 附近的工具实现为固定 `GET /v1/agents/me/permissions`，空参数，不接受任意认证 HTTP 或其他账号筛选。该范围与鲸栖原来的只读权限核验相符。它没有赋予鲸栖更改平台权限的能力。

### 媒体

工具参考第 419 行起明确支持任意时机的 `clawchat_send_file`，普通文件上限 100 MiB，支持 `as_document` 和 caption；图片、语音专用工具可以检查所需类型及补充尺寸或时长。不能继续沿用“官方不支持后台附件”的旧结论。

发行二进制偏移 103944039 的 `IF` 仅从活跃回合辅助判断 chat_type，没有强制要求存在活跃回合。偏移 103986743 的 `SR` 验证 Workspace、保护状态/凭据目录、打开并检查文件，读取成 Blob 后交给官方连接上传和等待 ACK。这些是官方已实现的保护，不另加鲸栖发送通道。

仍需保留的边界：公开参数未提供调用方预期内容摘要，返回值为 `sent/messageId/name/size`，没有通用最终媒体类型/MIME；发送端的打开和读中检查不等于验证交接前保存的业务产物摘要。业务数据位于受保护的 `.dsh` 中时，也不能直接把该目录放开，未来适配需使用允许的产物交接位置。另外，旧工具请求的未知结果没有公开只读查询替代；按同 request-id 再次调用工具不是独立只读查询，不能据此宣布历史恢复已迁移。

因此，后台发送这一项已补齐，完整媒体扩展仍不能按既定无损标准整体删除。后续不以链接替代附件，也不新增基础投递补丁绕过缺口。

### 普通正文与会话

Core 的 `sendReply` 路径内部等待实际发送，但没有把该正文的 messageId/结果交给 Runtime 作者；Runtime 的 deliver 接口也未提供通用结果依赖步骤。工具发送的 messageId 不能代替普通正文的送达结果，Client 输入受理也不等于正文发送成功。

官方 DSH Runtime 包中的 `runtimeStartContext`（`linux-x64.mjs` 第 2554 行起）传递 binding/chat/session/runtimeThreadId 回调和媒体缓存。已有 adapter prepare/start 不等于向第三方业务入口开放同一逻辑会话的调度权。仅靠自建 DSH 会话或普通文本提交无法保持当前通话的无输入准备、同原文字队列、前后处理和取消语义。

本轮没有用空提示、伪用户回合、另一活跃回合授权或第二套发送连接来补这些能力。
