# 基础能力需求：长期记忆

已确认功能需求；对应[技术设计](../technical/long-term-memory.md)。实际部署、启用与验收以[STATUS](../STATUS.md)为准。

对应[精简技术设计](../technical/long-term-memory.md)：复用原模块，只补真实聊天、整理额度及缺少的对话管理。首轮先跑通已验证ClawChat主人会话的新增聊天；旧历史全量回填及真实QQ/群聊联调后续推进，已有数据保留。

## 1 收敛的具体需求

| 编号 | 需求 |
| --- | --- |
| M-01 | Aurabot 原记忆模块继续作为唯一实现，沿用已有存储、召回和上下文注入，不另写记忆引擎。 |
| M-02 | 后台自动整理读取本实例获准的新增聊天，将有价值的内容保存为长期记忆。新实例按[产品设计的默认策略](../PRODUCT.md#日常相处与共同记忆)启用定时整理，已有实例按保存的设置运行。实际启用、时段和额度见[当前状态](../STATUS.md)。 |
| M-03 | 主人可通过对话记事、查询、纠正和删除记忆；实际调用原模块操作，以持久化结果为准。 |
| M-04 | ClawChat、QQ 按已确认身份关联共用获准长期记忆；私聊、群聊及不同参与者保留可见范围，完整会话不合并。 |
| M-05 | 自动整理纳入实例共同后台额度，只保留一条整理执行链；关闭、暂停或超额时不发起新的后台模型调用。 |
| M-06 | 保留已有事实、纠正、删除状态及整理进度；重复整理和重启不重复积累，不将已删除内容无条件重新导入。 |

验收对应检查：实际聊天经原模块提炼后可召回；对话管理真正落盘；身份隔离和共同额度生效；重启及重复处理保持一致。当前已有链路和未来补齐部分分别验收，不把模拟 QQ 结果计为真实双平台通过。

## 2 和原功能相比改动的位置

| 位置 | 原版做法 | 本项目要做的改动 |
| --- | --- | --- |
| 聊天流水入口 | 原[聊天中枢](../../vendor/aurabot/src/chat/hub.js)读取自己的 chatlog 文件 | 通过[记忆Adapter](../../src/memory-adapter.mjs)连接获准的DSH会话记录，转换为原模块可处理的日期、会话、发言人、时间和文本。仅提供整理数据，不将原流水清理动作映射成删除DSH原生会话。 |
| 身份和来源 | 原模块以 QQ 私聊、群聊及人物标识判断归属 | 沿用并补齐[可信身份映射](../../src/routing.mjs)，把平台及会话来源传给原模块，保持已确认的共享与隔离规则。 |
| 后台调用与触发 | 原模块有定时整理、空闲提炼、批次预算和进度控制 | 复用原机制，接入[实例后台策略](../../src/companion-policy.mjs)；每个实际后台请求受共同额度控制，按实例确认的时段和开关运行同一整理器。 |
| 对话管理入口 | 原版已有记忆工具、聊天命令和管理接口 | 保留原操作语义，通过当前宿主提供对话管理入口，尤其是纠正和删除；复用现有可信主人判断。 |
| 记忆核心 | 原[记忆模块](../../vendor/aurabot/src/modules/memory/index.js)和[整理逻辑](../../vendor/aurabot/src/features/memory.js) | 存储、提炼、检索及注入继续复用，不另实现一套业务。 |
