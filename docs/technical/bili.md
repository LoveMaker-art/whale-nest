# B站多平台开发设计

依据[已确认需求](../requirements/bili.md)描述实现与数据归属；实际部署、启用与验收以[STATUS](../STATUS.md)为准。

## 1 当前实现与复用范围

原[modules/bili](../../vendor/aurabot/src/modules/bili/index.js)和[createBili](../../vendor/aurabot/src/bili/duty.js)承担唯一读取/自动浏览业务；[activities](../../src/activities.mjs)保存共同经历，不再重复读取资料。[bili-tools](../../src/bili-tools.mjs)及账号模块保留登录、私信、动态、三连和监控等补充，两类能力使用同一账号、权限及任务身份。

| 能力 | 复用及收敛方式 |
| --- | --- |
| 视频读取与摘要 | 以原lookAt/watch为唯一读取业务，补结构化结果及实际coverage；activities不再自己重复view/subtitle/comments/digest，保留请求去重、经历保存与查询。 |
| 搜索、筛选与指定链接 | 保留现有搜索及筛选，命中后进入同一原读取入口。minAgeDays是“至少发布多久”，不能误映射成原maxAgeDays的“最多发布多久”。 |
| 自动浏览与分享 | 唯一现有活动任务调用原run，保留原选择和感想逻辑；补共同门禁、单视频限制及投递接缝，移除旧browse提示的第二次总结。原tick不独立再启动一轮。 |
| 评论及原资料/截图/弹幕能力 | 保留原业务和QQ权限检查；账号写入均接现有登录核验、操作额度及回执。截图结果可发两端，B站资料操作仍作用于B站账号。 |
| 登录、私信、动态、三连及消息监控 | 保留现有补充实现，原模块没有这些完整等价入口，不删除也不宣称上游已提供。接同一账号与调用身份，不再另装旧独立插件。 |

画面分析及弹幕等保留原功能和开关；未核实后端或未启用的能力不随本次迁移开启，实际coverage不得虚报。

## 2 必要改动位置

- [原bili/duty.js](../../vendor/aurabot/src/bili/duty.js)通过[兼容构建器](../../scripts/build-aurabot-host.mjs)补窄接缝：注入共同HTTP账号、输出结构化读取结果、接共享经历、任务预算及投递。默认原QQ调用语义保持，业务算法不手写复制。
- [bili-account](../../src/bili-account.mjs)作为唯一凭据、登录核验与账号操作回执写入方。原bili.cookie改为读取投影，登录/登出不再各改一份；不在模型工具结果中暴露Cookie。
- [bili-http](../../src/bili-http.mjs)及[bili-rules](../../src/bili-rules.mjs)保留现有接口补充、筛选和账号限额；原API可直接复用的读取继续使用。原工具的账号写入也需接同一操作门禁，不能绕过已有未知回执和日限。
- [activities](../../src/activities.mjs)保存唯一可供两端查询、日记取材的经历。原state.history从同一经历形成兼容视图，不再成为第二份独立活动写入来源；旧历史按来源身份迁移，不能凭同一BV号误合并两次实际活动。
- [bili-tools](../../src/bili-tools.mjs)、[companion](../../src/companion.mjs)统一装配和工具注册：同名bili_watch/bili_comment等只暴露一个执行器；QQ原工具权限保留，CC入口调用同一业务。原工具名可保留兼容，但不能注册两份同名工具后依赖覆盖顺序。
- [bili-inbox](../../src/bili-inbox.mjs)继续承担唯一消息监控；提醒接[共同投递](proactive-delivery.md)，原自动回复轮询不并行开启。原自动互动功能保留，后续明确启用时仍要进入同一限额和回执。

## 3 数据与两端行为

账号、rules、inbox、activities等旧route scope按[共同迁移规则](proactive-delivery.md#3-状态归属与迁移)改为实例及主人归属，保留凭据、账号generation、UID分区、游标、通知次数、经历、筛选和未知回执。各入口核实已关联主人，平台route仅用于Session及投递；共享业务归属不能通过删除身份检查实现。

手动请求返回原会话，账号站内操作对象按该次明确请求确定；自动分享及提醒用全局首选。一次浏览只执行一次，分享失败不重读或重写站内操作。自动浏览每天最多一轮、先读一个视频，后台实际模型调用含原run内部调用，逐次计入5次共同额度；自动账号写入保持关闭。

原模块内部的运行、评论及回复计数与现有规则需建立唯一计量入口，保留两者既有已用次数；不能一边独立计数、一边在共同规则重新算为零。不同功能日限语义不等价时分别保留约束，实际执行同时满足，不用字段同名推断可覆盖。

## 4 回归与交付

复用现有bili-tools/native、activities-native、account、rules、inbox/native及native-qq测试入口，验证同一原读取/自动浏览实际被调用、同名工具不重复、搜索筛选不退化、共用账号及经历、每日额度、真实资料覆盖与失败状态。覆盖旧scope迁移、账号更换、重复请求、未知写入回执、监控游标及重启。

ClawChat用公开内容自行完成搜索、指定链接、摘要、经历查询及日记来源检查；B站真实账号验收按用户决定保留为非阻断项。登录、评论、私信、动态及三连只有真实账号结果才能标为实测，不因模拟通过改变其状态。QQ先真实SDK与可控网关，绑定和真实账号动作另行授权。
