# 回复与通知的开发设计

本轮属于首版收尾，落实[产品的回复与通知原则](../PRODUCT.md#回复与通知的表达原则)。交付覆盖 ClawChat 和 QQ 的消息正文。用户操作、路由、状态和回执由程序确定，模型依据可信事实用当前人格组织表达。现有聊天回合承担当轮表达，程序主动发出的通知复用一处文案生成。模型受限、超时或输出不可用时，必要进度、结果和下一步使用简洁兜底。

## 按出站路径审查

| 场景 | 当前路径 | 本轮处理 |
| --- | --- | --- |
| 日常文字、群聊、ASR、普通语音和表达联动 | DSH 当前回合组织正文，语音合成读取同一回复；图片、表情和音频各有投递结果 | 复用现有回合，补充统一事实表达要求。附件名称、类型和播放标签仍由平台提供 |
| 人格、记忆、心情、提醒设置、B站手动操作、日记查询、表情、图片、歌曲及 QQ 专属工具 | 业务工具返回结果，当前回合读取结果后回答 | 复用工具调用和模型回合。模型依据动作及回执回答，引用、文件和用户指定正文照原文处理 |
| ClawChat 发起 QQ 登录、刷新、绑定、查询、断开 | 适配器提供结构化操作结果，模型生成正文，程序附必须原样显示的内容 | 已有正常路径。补齐操作已有明确结果，模型无最终正文的情况；旧回合回放保留历史原文 |
| QQ 扫码及主人关联的后台进展 | 登录轮询、网关状态和关联事件先确定实际结果，入现有发件队列 | 将状态和必要口令交给共用表达逻辑。扫码、手机确认、过期、限登、关联和聊天通道启用各自按实说明 |
| 歌曲后台跟进 | 保存后发送待确认、生成失败、取回中断或等待超时，由程序通知原会话 | 使用实际任务状态和原作品信息，保留原任务，提示按需查询或恢复 |
| B 站消息提醒 | 检查账号和提醒偏好后入队，附作者、原片段和链接 | 模型表达提醒原因；站外正文及链接作为引用，原样放在正文之后 |
| B 站主动分享、主动联系与私人日记 | 原业务模型已生成分享或联系内容；日记有生成正文和程序化引言 | 分享、联系和日记沿用原模型结果。日记直接发送带日期的已归档正文，去掉重复引言 |
| QQ 原生命令及慢工具提示 | 命令由原 Hub 执行，慢工具有固定的进度通知 | 复用共用表达逻辑。命令、参数和必要结果可核对，执行失败使用安全摘要；慢工具结束后取消尚未发出的进度提示 |
| 权限确认、公开发布及运维日志 | 授权流程有必要的固定字段，公开内容使用已确认正文，技术日志留在运维入口 | 保留权限、用户授权原文和协议字段。用户提示依据实际业务状态组织 |
| ClawChat 实时通话 | 原私聊会话的模型回复经 TTS 在 Liveware 播放，连接和设备状态由通话页面显示 | 语音答复沿用当前人格。通话内容带来源标记进入原会话历史，通话界面显示字幕和进度。[通话设计](../PRODUCT.md#实时通话) |

## 实现顺序

1. 在已验证发件目标、执行实际投递之前组织文案。沿用现有后台模型配置、时段及用量账本，每条最多一次调用，只传必要的结构化事实和当前人格。该模型请求只生成一小段正文，无工具、历史、凭据、目标选择和发送权限。
2. QQ 登录/关联、歌曲、B站提醒接入同一表达逻辑。程序附上完整口令、原引用或档案正文。生成失败、禁用或超时走简洁兜底，现有后台模型额度为零时直接使用兜底。待发文案固定后随原意图保存，发送延迟或恢复不会重写文案。路由变化时，依旧由原任务策略决定是否发送。
3. 兼容原 QQ Hub 的命令结果及需要展示的慢工具进度；ClawChat 的 QQ 管理当轮有确定结果但没有模型正文时，适配器可发一次兜底。旧通知和已完成或待核对的投递保留既有回执语义。程序统一附加必要字段，避免正文遗漏连接口令。
4. 完成本地真实入口回归后，再在测试机核对候选版本、现有会话、ClawChat 原通道和配置。测试使用受控状态和替身模型覆盖不适合在用户账号重现的故障。

## 验收条件

- 同一条开启模型的程序通知实际取用模型正文；禁用、失败、超时或输出空白时发送对应兜底。自动调用遵守原额度，重启和重复处理不重复计费或发送。
- 扫码、连接、生成、保存、发送、送达待确认分别表述。二维码发送失败或回执未知时，不宣称已送达；必要口令和原文可验证。
- 既有模型回复、原 QQ 命令副作用、回复会话、主动首选、群聊权限和历史重放保持原行为。模型输出失败不会阻断已经得到的必要结果，迟到进度不抢在最终结果之后发送。
- 验收记录分别标明本地测试（替身模型与传输）、ClawChat 实机、QQ 实际账号、平台媒体及后台收费模型。沿用当前账号状态与功能开关。
