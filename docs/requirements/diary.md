# 日记与经历档案需求

已确认功能需求；对应[技术设计](../technical/diary.md)。实际部署、启用与验收以[STATUS](../STATUS.md)为准。

## 1 内容与来源

- 写入当天实际浏览、完成的活动及相应感想；保留时间、来源和实际取得的资料范围。失败或未完成的活动不写成已完成。
- 聊天原文、私聊摘要及私人长期记忆不作为自动取材来源。人格和心情可影响语气，不用来证明发生过某件事。
- 感想基于实际素材，不虚构出门、吃饭、观看完整视频等经历。没有可用活动记录时不硬编日记。

## 2 用户体验

| 场景 | 需求 |
| --- | --- |
| 整理 | 沿用每日北京时间21:00、有素材且额度允许时最多整理一篇；也能通过对话要求整理。自动生成的启用继续按既有开关，不因确认文档开启。 |
| 查看 | 可说“看看今天的日记”“翻一下昨天的日记”；在发起询问的平台展示。 |
| 两端使用 | 同一份获准日记档案由同一个能力管理，明确关联的主人可从QQ或ClawChat私聊查询，不自动汇入两端聊天全文。 |
| 完成通知 | 启用通知时继承[全局主动消息首选](proactive-delivery.md)，受共同次数和额度限制，不另问一次接收平台。 |
| 发布 | 默认私人保存；发QQ空间或ClawChat动态需明确发布位置、正文和受众，通知首选不决定公开发布。真实活动记录也不自动视为可公开。 |
| 管理 | 按日期查看、重新整理或删除；保留既有版本和删除状态，自动任务不重建已删除日记。 |

## 3 复用和数据边界

优先复用原diary中符合活动取材规则的生成能力，现有私人档案负责保存、查询及删除，不再另写一个平行生成器。原QQ空间普通/图文能力保留，首轮不因接入而开启聊天取材或自动发布；后续启用其他来源时单独确认范围。

已有日记、经历、版本、来源、删除状态及发布回执继续保留，不批量重写历史。经历记录是日记的事实素材，不等于新增一套用户长期记忆；其他参与者和群聊不获得主人私人档案管理权。

## 4 验收重点

1. 有活动时正文能对应实际来源；只有私聊、没有活动时不自动生成一篇聊天日记。
2. 同一份档案可由已关联主人在两端查询，回复原询问会话；通知则遵守全局首选。
3. 私人日记不自动发布，QQ空间与ClawChat动态的发布权限和回执分别检查。
4. 重复整理、重启及删除不产生重复日记或恢复已删除内容；旧档案保留。
