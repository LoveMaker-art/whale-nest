# 平台唱歌接入设计

依据[已确认需求](../requirements/singing.md)描述实现与数据归属；实际部署、启用与验收以[STATUS](../STATUS.md)为准。

## 1 复用与替换位置

原[song 工作室](../../vendor/aurabot/src/song/studio.js)执行原歌下载、人声分离、RVC 换声及混音，与本次平台生歌目标不同，不能只改一个模型名称后继续运行。保留固定上游源码及校验，在[现有宿主](../../src/companion.mjs)的原模块管理器中接一个平台唱歌实现；同一实例不同时启用原 RVC 流程。

沿用原[song 模块](../../vendor/aurabot/src/modules/song/index.js)的主人权限、异步完成通知和完成经历及心情联动。平台生成、任务状态和歌曲档案由两端共用，媒体回到发起会话。ClawChat 的[作品页](#6-clawchat-作品页)读取同一份档案。演唱预设由平台歌曲服务管理，日常 TTS 沿用现有音色设置。

## 2 平台请求

用[现有 provider 读取器](../../src/platform-provider.mjs)取得可信基址与原 Key，依已核查生产合同使用同一可信 origin 的 MusicHub 路径；不能把 `/api/jobs` 错拼到 `/v1` 下。新增的轻量客户端只处理平台 HTTP，不下载模型或引入整套 App。

1. 明确请求后准备歌词和风格，提交 `POST /api/jobs`，保留返回任务 `id`。
2. 通过 `GET /api/jobs/{id}` 查询状态；完成后下载 `/api/jobs/{id}/audio.flac`，平台提供乐谱时可一并保存。
3. `voice_preset` 默认使用平台 `none`，声音随风格生成；明确选择固定预设时才使用已核实的 `hope`。不传未经支持的 TTS 音色 ID、自定义角色模型或参考人声。
4. 文件保存后，经同一投递入口返回发起会话。复用[现有媒体发送](../../src/media-delivery.mjs)及 QQ 原 Hub，核实实际格式后必要时轻量转码；不把本地文件或临时 URL 当作送达。

具体字段和错误处理在开发时对照固定官方客户端复核；此处不编造服务端并发、时长或幂等保证。平台主要推理在远端，实例仅准备文本、查任务、保存文件及发送；下载按流限制大小，不照搬整文件加载。

## 3 状态及恢复

复用现有私有媒体目录、readState/writeState 及发送回执，记录稳定请求标识、原会话、参数、任务 ID、生成状态、作品文件和发送结果。两端工具调用同一入口，不按平台复制业务或作品库。

提交前保存请求，收到 ID 后立即保存；重启后有 ID 的任务只继续查询。创建响应丢失则标为待核对，不自动重新付费提交。生成成功后先保存作品再发送；下载或发送失败仅恢复对应步骤。查询、重发及跨端查看沿原作品，不重新生成。首轮按现有实例资源串行处理，不新增多任务调度系统。

## 4 回归及上线边界

沿[现有开发流程](../../AGENTS.md)和[直接更新入口](../DEVELOPMENT.md#现有实例的直接更新)交付。必要回归覆盖原权限、唯一执行入口、正确会话、保存早于发送、未知创建不重提、重启查已有任务及两端共用作品；原 TTS、图像、记忆和后台开关保持可用。

真实生成与歌曲投递遵循需求中已确认的费用及限定用量；生成、保存和平台发送分别验收，不将其中任何一项替代客户端实际播放或听感。既有真实结果、待验效果和新增用量范围统一见[STATUS](../STATUS.md)及对应任务证据；生视频保持暂缓。

## 5 已实现的接线

[song-client](../../src/song-client.mjs)是唯一MusicHub HTTP执行体，使用现有配对provider认证，创建前持久化意图、收到任务ID立即保存；重启、恢复只查已有任务，不重新POST。按流保存到media/outgoing/songs，首轮限制32MiB。优先使用平台任务实际返回、与原job匹配且同一可信origin的audio_url，支持WAV/MP3/FLAC；缺省仍沿原FLAC路径。保存前识别音频头，元数据查询默认30秒，文件下载120秒；旧ready任务恢复时先补查已存在的音频入口，不重新生成。没有使用本地推理模型或转码程序。

[song-adapter](../../src/song-adapter.mjs)在原模块管理器占用唯一song位置，暴露sing_song和companion_songs。原RVC工作室不装配，兼容status明确RVC不可用，语音后处理不误用平台唱歌服务。仅已关联主人当前手动私聊可生成；同一可信回合复用请求，一次处理一首。两端共用media/song-requests中的记录与作品，完成联动沿原memory/mood接口及song/sung事件，自测不写虚构经历。

后台定时器只查询已由主人创建的任务并保存、投递结果，不自行创作，不占原5次后台判断额度。20分钟仍未完成或发生查询/下载异常时保留原任务并暂停自动处理，错误通知进原outbox；recover只恢复原结果并保持发送等待，send需主人明确要求。QQ使用原Hub语音出口并传音频字节，不要求网关能读Agent服务器路径；只有原OneBot错误分类确认未送出时才降为文件，未知不换方式重发。ClawChat复用原媒体上传，允许平台把FLAC分类为音频或文件，回执记录实际类型；普通媒体发送的既有严格类型检查保持。

更新入口增加--songs，继承现有provider配置和全部已启用能力；--probe-prompts可把已标记的查询对话并入同一次更新探针，减少额外停机。回退到m3.21及更早会关闭不兼容song写入方，保留歌曲、平台任务及不确定回执；不启动原RVC替代它。

## 6 ClawChat 作品页

宿主在启用 `singing.playback` 时通过独立的回环 HTTP 服务提供[作品页](../../src/song-playback.mjs)。默认由原 Connect 绑定发布私有应用。应用根路径打开 SongSmith 首页，顶部提供「创作」「我的歌」「发现」。每首歌仍以既有 `operationId` 寻址。作品组和版本从同一份歌曲任务记录映射。重启保留原始任务、版本、音频、歌词和乐谱。作品支持分段播放、播放队列及音频、歌词和乐谱下载。乐谱通过原任务读取并缓存在对应记录旁。

[SongSmith 原版页面](../../vendor/platform-liveware/songsmith/app.html)及旋律提取逻辑用于哼唱、手绘和试听。录音在浏览器内转换成 ABC 乐谱，上传乐谱和生成草稿。页面从 Connect 激活记录核对 Agent、主人和私聊，产生预填草稿的 ClawChat 链接，也支持复制。根据本轮草稿引用核对谱和原版本。按旋律唱短歌走一次 MusicHub 带谱任务。扩展为整首使用原版 ABC 工具把旋律放进整首谱，再提交演唱。两阶段各自在提交前保存任务意图，确认结果不明时保留原记录。逐句精修把修改、原版本与是否保留旋律带回私聊，完成后追加稳定版本号。[固定平台发布物](../../vendor/platform-liveware/SOURCE.json)

[作品管理](../../src/song-studio.mjs)保存封面、分享、互动和归档状态。删除确认后从曲库撤下作品并撤回分享，原任务及音频保留供回退。好友模式只列指定分享版本。未分享的歌曲、原谱、私聊入口和其他作品数据归主人。点赞和评论依赖中继认证的用户身份和配置的受众。撤回立即停止好友访问。公开运维试听继续只返回指定样曲。可选[歌词精校](../../src/song-alignment.mjs)由主人启动并使用对齐服务返回的时间锚点。

## 7 原版创作语义与模型接线

完整核对范围见[SongSmith 适配清单](../tasks/songsmith-adaptation.md)。[写歌指引](../../src/song-guidance.mjs)由 ClawChat 和原模块共用，实际进入 DSH 模型请求。指引保留原版的主题澄清、歌唱语言、英文曲风、旋律读取、短歌约束、精修、等待链接和结果确认，沿用鲸栖当前人格与主人权限。

哼唱、画线默认采用 `graft`，将片段扩展到整首；用户明确选择短歌时采用 `whole`。上传提交时复用原版 ABC 解析和乐句划分，核验并保存来源、速度、调、小节、时长、段落、逐句音符数和质量资料。旧旋律档案可以从原谱推导同样的资料，查询不会改写旧档案。

`companion_songs draft` 读取当前草稿，返回可读乐谱、旋律资料和填词计划；精修还返回原版本歌词及曲风。`sing_song` 自动解析本轮可信引用，成功回执明确返回旋律来源、采用模式及项目进度页。短歌在任何平台请求前校验段落、乐句和发音单位；保留旧整曲时按原歌词的结构与逐句发音数量约束修改。汉字和韩文按字符计数，英文及其他拉丁文字的音节使用估算，不代表声学识别。已受理旧任务继续使用原参数恢复，不因新规则重新提交。

制作中的项目页仅主人可见，查询阶段不重新生成。作品查询支持原歌词、曲风、原谱与实际截断提示。主人可显式取回歌词或乐谱文件，以及设置至多六个标签；文件发送沿原通道回执去重。六种页面语言使用对应的创作入口指令。

主人要求改谱时，修改稿作为新版本输入，原谱保留。变速校验全部音符及小节不变；修改编曲保留音符；局部旋律修改校验指定小节外及伴奏音符不变；段落增删重新核验词谱结构。新版曲风中的速度与变速后的乐谱一致。没有用户对应修改要求、没有原作品或校验失败时，不提交生成。

作品歌词可按实际谱上的音符推算位置，页面明确区分“按谱推算”和“已精校”。对齐缓存独立保存，不通过页面查询覆盖歌曲任务或发送回执。多个读取进程使用独立临时文件缓存原谱，避免争用。没有可读乐谱时不编造句子时间。

[主人后台](../../vendor/platform-liveware/songsmith/admin.html)统计实例曲库和已配置的受邀听众。关闭评论后，听众看不到历史评论，也无法新增评论。重新启用时恢复历史评论。好友和试听用户无法打开后台或更改设置。

歌曲进入 ClawChat 私聊且媒体回执已确认时，附送作品链接。`companion_songs open` 可以只发作品入口。链接从该实例已核验的私有应用地址生成，用原 outbox 回执按请求去重。QQ 沿用原媒体发送。同一歌曲和乐谱的验收方法见[开发说明](../DEVELOPMENT.md#歌曲-liveware)。
