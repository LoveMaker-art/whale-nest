# 基础能力需求：心情

已确认功能需求；对应[技术设计](../technical/mood.md)。实际部署、启用与验收以[STATUS](../STATUS.md)为准。

## 1 收敛的具体需求

| 编号 | 需求 |
| --- | --- |
| E-01 | 复用Aurabot原心情，保留互动推动、时间衰减、状态及历史持久化；不另写算法。 |
| E-02 | 同一实例两端共用一份心情；真实互动按身份/场景参与变化，系统任务和运维自测不刺激心情。 |
| E-03 | 心情及表达提示进入当前模型上下文，其他参与者看不到含主人私聊内容的原因。 |
| E-04 | 语音/表情概率、QQ分段间隔和群参与读取原effects；语音可按心情使用同一音色的普通、兴奋、难过表达，继续服从权限、偏好、频率及额度。 |
| E-05 | 默认关键词模式，无额外判心情模型请求；模型判断作为后续可选能力另行核对。 |

## 2 用户可见规则

自动语音基础概率15%、表情35%，乘原心情倍率；自动语音最多80字。主人明确文字偏好优先，手动已发媒体不自动重复。语音获平台确认后可用短标记代替完整文字显示，失败保留原文；图库支持对话管理，自动收图及QQ收藏分别控制。

心情的积极两档使用兴奋表达，平常使用普通表达，低落两档使用难过表达；保持一个默认音色。五档文字风格和原倍率继续区分，不承诺五种声学强度，不因情绪变化额外生成一条语音。ClawChat单条回复不为模仿QQ分段而增加等待。

## 3 复用与改动位置

| 位置 | 处理 |
| --- | --- |
| 原mood/createMood | 评分、衰减、存储和effects继续复用，唯一mood.json |
| 可信互动及上下文 | 对接原observe，排除重复、系统及自测，过滤非主人可见原因 |
| 原QQ Hub及共同表达 | 共用原选择函数和倍率；QQ保留delay/chatty，CC走现有媒体出口 |
| 原voice的平台接缝 | 合成前读取心情，按已验证模型/音色映射表达，重放复用原音频 |

## 4 验收条件

真实互动按原规则改变状态，重启保留；实际请求获得适用心情提示且不泄漏私聊原因；两端读取同一状态。表达验证选择、权限、确认后显示、失败回文字、取消及重启去重，语音试听与自然对话自动触发分别留证。

真实QQ分段/群参与须账号联调；不能以模拟网关或倍率计算代替客户端效果。模型判心情、自动视觉起名和其他语音风格不作为本轮前置。
