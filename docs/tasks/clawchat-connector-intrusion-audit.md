# 当前测试机的 ClawChat 连接器侵入与重合审计

核验日期：2026-11-24。对象为 SSH 端口 20037 的测试机。本轮只读取运行事实、比较固定源码、执行隔离验证并写报告；没有修改功能、切换服务、发送消息、调用真实模型或发布版本。

## 1. 先说结论

**现在运行的仍是我们修改并重新编译的 ClawChat Core，不是纯官方连接器。** 官方的消息连接、认证与上传能力被复用，但我们在它内部增加了业务需要的入口，并用自己的启动配置运行这份程序。此前把它概括成“五个补充接口”不够完整。

这次确认有六类直接功能改动：媒体发送、权限读取、通话借用原私聊会话、正文确认后的表情回调、应用中继启停，以及此前漏列的发送结果查询命令。另外还有启动覆盖、复制并修改宿主运行文件、修改官方 Runtime/Bridge 构建产物，以及读取连接器内部状态等耦合。

**有些基础能力确实与官方重合；“存在重合”不等于“现在删掉就能保持功能”。** 需要先改变鲸栖调用它们的方式，再切换实际运行的程序。不能把当前依赖说成永久保留定制 Core 的理由，也不能把尚未验证的替代路线说成已经适配。

上一轮修好的只是鲸栖更新准入：不再拿连接器、DSH 版本和定制能力登记拦住升级。**这没有删除下面的运行依赖。**

## 3. 六类直接改动

### 3.1 媒体发送：基础动作重复，调用条件不同

**我们加了什么：** 在 Core 工具目录和执行器中新增 `clawchat_send_media`。它读取文件、上传、组合媒体消息、调用原有连接发送并等待回执。没有另建第二条 ClawChat 消息连接，但确实进入了官方 Core 的工具执行代码。

**官方已经有什么：** `clawchat_send_file` 已支持图片、音频、视频、文件、上传和发送确认。官方也校验 ACK 的消息编号，不能把“官方没有真实回执”当成保留补丁的理由。[官方工具目录](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/agent/tool-catalog.ts#L221)、[官方执行器](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/agent/tool-executor.ts#L118)、[ACK 协议校验](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/clawchat/protocol.ts#L391)

| 对比点 | 官方文件工具 | 当前鲸栖路径 |
| --- | --- | --- |
| 何时能发 | 必须存在正在处理的 ClawChat 对话；按当前发言者判断目标权限 | Core 新入口不做这项检查，鲸栖调用方核对主人、会话及受控文件 |
| 文件放哪里 | 必须在工作区，且拒绝 DSH/连接器状态目录与凭据位置 | 先制作发送快照，放在 `dataDir/media/outgoing/artifacts` |
| 实机目录关系 | 工作区是 `/home/node/dsh` | 快照位于 `/home/node/.dsh/companion/aurabot-v1/media/outgoing/artifacts`，既不在该工作区，也属于官方拒绝的 DSH 状态目录 |
| 参数与返回 | 路径、目标、说明、是否当作普通文件；回执返回消息编号、名称、大小 | 另有文件摘要、预期媒体类型、时长、宽高等参数，并记录实际媒体种类 |
| 发送结果不明确 | ACK 超时有未知状态分类，其他异常须按实际路径判断 | 提交后的非明确拒绝进一步按未知结果保存，避免重发 |

这意味着：**当前连普通聊天里的发图，都不能只把工具名改成官方的名字。** 还要改变快照交接位置和参数转换。后台恢复、QQ 发起后回传 ClawChat 等路径，还要另查发送时是否存在官方要求的对话上下文。[官方发送策略](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/agent/send-file-policy.ts#L36)

不能把所有后台行为一概判为不可用。当前正文后表情回调仍发生在原 ClawChat 对话清理之前，自动语音也可能仍在该对话中；这些条件与脱离对话运行的后台歌曲恢复不同。更不能借另一个偶然活跃的对话来证明当前任务有发送权限。

当前媒体入口的实际调用范围包括：

| 调用方 | 受影响的用户功能 |
| --- | --- |
| [media-delivery.mjs](../../src/media-delivery.mjs) | 普通附件发送与发送结果查询 |
| [voice.mjs](../../src/voice.mjs)、[expressions.mjs](../../src/expressions.mjs) | 手动语音、自动语音、自动表情 |
| [stickers.mjs](../../src/stickers.mjs) | 手动发送表情 |
| [image-adapter.mjs](../../src/image-adapter.mjs) | 生成图及已有作品的回传 |
| [song-adapter.mjs](../../src/song-adapter.mjs) | 歌曲成品、歌词和乐谱文件、未定投递恢复 |
| [qq-connection.mjs](../../src/qq-connection.mjs) | QQ 登录二维码及登录提示图片的发送、补发 |
| [companion.mjs](../../src/companion.mjs) | B 站截图等受控图像回传 |

其中歌曲的 `create` 先返回任务状态，定时 `tick/advance` 再取回和投递，存在离开原聊天后的发送路径；不是所有歌曲发送都始终停留在最初的聊天回合内。

**直接删除的结果：** 不改调用方就删除工具，以上路径会遇到“未知工具”；只改工具名，则当前快照目录会被官方拒绝，部分后台路径还会被发送时机检查拒绝。

**合理清理方向：** 普通对话中可等价的上传、发送和回执应交给官方。鲸栖保留作品原件、受控发送快照和任务记录，快照交给官方许可的工作区。后台发送需要核实官方是否能提供可信任务入口；放宽官方目录检查、伪造活跃对话，均不能算完成解耦。类型显示、时长、摘要、未定结果和重启去重仍需回归，当前未实施替换。

### 3.2 权限读取：平台有能力，插件缺少同样的调用入口

**我们加了什么：** `clawchat_get_agent_permissions`，复用连接器现有认证读取 `GET /v1/agents/me/permissions`。

**官方已经有什么：** 平台本来就有该权限接口、临时允许窗口及权限变化事件。我们没有另造权限规则。但 `0.2.22` 的 Connect 工具目录没有对应读取工具，公开插件 SDK 也未暴露任意认证 HTTP 请求入口。账户资料查询不等于权限与动态受众查询。[平台权限协议](https://github.com/clawling/clawchat-plugin-install-cli/blob/dc17738334ddf168f9a2761e4de24c590c892c57/docs/agent-protocol.md#L394)、[官方插件 SDK](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/plugin/sdk.ts#L245)

**直接删除的结果：** [diary-publisher.mjs](../../src/diary-publisher.mjs) 无法完成权限与受众核对，ClawChat 日记发布、删除会停止。不能改成查不到就默认允许，也不能将跳过受众检查当成等价清理。

**合理清理方向：** 由官方提供固定的只读工具或受控认证入口，再移除我们的目录项。直接把登录令牌交给业务、自行管理刷新，只会转移耦合；本轮没有把它作为已验证方案。

### 3.3 通话共享会话：修改了官方的会话管理接线

**我们加了什么：** `withPrivateVoiceSession`。不只是一个函数名，它穿过插件宿主、SDK、账号绑定、任务队列和会话执行器，借用当前主人私聊的同一运行会话，并核对插件激活代际、主人、会话、模型及取消信号。

**官方已经有什么：** 同会话排队、客户端提交、取消，以及主人和绑定校验。官方不是没有这些基础能力。但公开 Runtime 上下文没有“把 Core 正在管理的原会话句柄借给通话代码”的同等入口；客户端提交也不是当前实时通话实现的直接替代。[官方会话提交与队列](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/runtime/connect-runtime.ts#L274)、[原会话句柄管理](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/runtime/session-turn-executor.ts#L65)

**直接删除的结果：** [platform-voice-bridge.mjs](../../src/platform-voice-bridge.mjs) 会因缺少入口而无法提供共享会话通话。普通文字聊天不等于必然全部失效，但通话不能继续按现行方式工作。

**合理清理方向：** 研究官方客户端提交路径，或将统一的会话管理放回鲸栖 Runtime。无论哪种，都要证明聊天与通话不会同时写原生会话，切换会话、打断、取消、播放过的前缀和重启恢复仍正确。另开一个 DSH 会话不满足“同一原私聊会话”的现行要求。

### 3.4 正文确认后发表情：改动了消息完成后的处理流程

**我们加了什么：** Core 在正文完成实际投递后调用 `afterClawChatReply`，鲸栖再决定是否发送已经选好的表情。表情选择本身在业务中，但这个通知点加在官方消息处理代码里。

**官方已经有什么：** 实际发送会等待 ACK，并记录消息状态；也有回合完成日志。问题是这些内部事实尚未以同等的 Runtime 回调公开。官方先缓冲正文、在回合输出完成后投递，所以模型生成结束、`yield` 返回、界面出现文字，都不能直接当成正文已送达。[官方输出缓冲](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/runtime/turn-surface.ts#L47)、[官方实际投递](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/runtime/connect-runtime.ts#L714)

官方 `reply_sent` 日志是在交给传输层时写入，不是 ACK。`turn_finished` 在正常投递之后，但也可能对应没有正文或不回复的回合，单独看它不够。[ACK 持久化](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/clawchat/ws-client.ts#L874)

**直接删除的结果：** 当前等待回调的自动表情不会补发。把发送动作移到生成结束后，会改变先确认正文、再发表情的顺序保证；把表情放进同一条正文，则改变消息呈现方式。

**合理清理方向：** 可评估把正文与表情作为两条有序输出交给官方投递，或由官方提供送达事件。观察私有日志/数据库也有耦合，不能把它包装成天然稳定的公共接口。当前没有完成整条表情业务的等价替代验证；下文第 9 节补充了官方顺序输出的隔离验证。

### 3.5 Liveware 中继：复用了官方程序，但自己接管启动与重试

**我们加了什么：** 在 Core 账号绑定连接后启动官方 Liveware agent，退出后重试，认证停止或绑定关闭时停止。我们没有自写另一套隧道协议，但把应用中继生命周期放进了消息连接器。

**官方已经有什么：** 自定义应用创建、权限、隧道绑定、注册，以及官方 Exposure 的启动、恢复和资源管理。当前应用发布也在使用官方结构化命令。[官方应用命令](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/agent/agent-liveware.ts#L46)、[官方中继控制](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/service/liveware-control.ts#L171)

区别在于：官方 Exposure 发布每个绑定所选择的一个 Managed Web App；当前鲸栖提供两个独立应用，且官方 Exposure 在实机已关闭。官方面向 Agent 的应用管理命令也没有让业务直接控制常驻 agent 进程。[官方应用选择](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/plugin/managed-web-app-registry.ts#L471)、[官方设计决策](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/docs/adr/0026-broker-agent-managed-liveware-commands.md#L11)

**直接删除的结果：** 若没有另一个受控中继先接管，两张网页即使本地服务仍在，也可能失去外部访问。官方“有中继”不代表当前已经由它的标准生命周期管理这两个入口。

**合理清理方向：** 验证官方生命周期能否管理当前两个应用及其同一账号认证，或为鲸栖提供符合官方规则的应用贡献方式。需要覆盖两个入口共存、服务退出、认证轮换、重启恢复和资源清理。聚合成一个新页面属于体验变化，本轮没有实施或默认批准。

### 3.6 查询发送结果：此前遗漏的第六类 Core 改动

**我们加了什么：** `tool status <requestId>`，只读取已保存的工具请求结果，不重新提交操作。

**官方已经有什么：** 原本已有持久工具请求和内部 `getToolRequest`。但 `0.2.22` 的 CLI 未提供同样的只读查询入口，控制面也没有已确认等价的工具状态查询。重复运行同一个 `tool call` 仍经过提交/等待逻辑，记录不存在时可能新建操作，不能直接当成只读查询。[官方 CLI](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/service/cli.ts#L496)、[原持久查询](https://github.com/x-metheus/clawchat-plugin-connect/blob/1ac78bcd51f60121d98bfe3def43a2bdba230a5b/src/persistence/state.ts#L2968)

**直接删除的结果：** 媒体发送和日记发布遇到断线、超时后，不能按现有方式核对未知结果。已经确认的历史记录不会因此变成未发送，但等待核对的请求会失去当前恢复入口。

**合理清理方向：** 优先接官方只读查询接口。也可以评估复用我们已有的只读状态适配层，但这会继续依赖数据库结构，必须覆盖账号归属、失败原因、无记录、未决结果和禁止重发。这项有明确的迁移思路，不能只删命令分支而不改调用方。

## 4. 六项之外的运行与部署耦合

### 4.1 启动目标指向定制目录

当前启动链路是：系统服务启动鲸栖的 `serve-media.mjs`，该脚本读取扩展登记，把官方宿主的 agent 启动目标改成复制出来的运行目录，再由该目录启动定制 Core。

这不是简单地加载一个普通业务插件。[启动脚本](../../deploy/serve-media.mjs) 和 extensionHostConfig（历史文件已退役，原文保存在Git记录） 都在现役路径中，实机常驻进程也已核对。

官方原始二进制保留且摘要正常，不等于消息实际由它处理。**删除仓库里的补丁文件也不会改变已编译的运行程序。** 反过来，直接删定制目录或启动登记会使现有启动目标缺失。

从当前代码可以确认：该覆盖项固定指向定制目录，官方包升级本身不会自动重编译我们的 Core。平台升级是否另行覆盖该启动设置，本轮没有做切换验证，不能断言必定离线或必定保持兼容。

### 4.2 复制官方宿主文件并修改模型转换

connector-extension.mjs（历史文件已退役，原文保存在Git记录） 会复制官方 `runtime`、官方插件包、更新技能和 Liveware 程序，并在 `runtime/lib.mjs` 中增加 `clawling-voice` 模型别名，供特定模型选择关闭思考的语音路径使用。

当前命令启动器还做分流：状态与主人查询交给固定官方包里的程序，其余命令交给定制 Core。它们共享原配置，不代表建立了两条常驻消息连接，但保留了对旧官方目录的文件依赖。

删除模型别名不必然让通话完全断开；按当前选择逻辑，它会失去这一特定模型的快捷选择，实际时延影响尚未验证。宿主模型转换与通话选择应评估迁回鲸栖配置层，而不是继续替换官方源码片段。[模型选择逻辑](../../src/voice-model.mjs)

扩展准备还固定要求官方源码提交和模型转换文件摘要。当前官方 `0.2.22` 的上述 13 份被改文件与 `0.2.20` 相同，整个仓库提交号仍不同，所以现准备代码仍会拒绝直接套用。这是自编译维护方式造成的限制；不能盲删校验，也不能把它继续放进普通鲸栖更新流程。普通更新已与该重建入口分开。

### 4.3 官方 Runtime/Bridge 被构建器按源码文字插入逻辑

[build-runtime-base.mjs](../../scripts/build-runtime-base.mjs) 和 [build-connect.mjs](../../scripts/build-connect.mjs) 不是只写一份外部配置：它们核对固定官方资产，然后按特定源码字符串插入鲸栖逻辑，生成随鲸栖包发布的适配器和 DSH 桥。

这些插入包括业务工具装载、主人路由、原生输入去重、会话生命周期、语音来源、取消与播放信息、表情调用、聊天可见历史过滤等。它们与官方本来已有的会话、工具、历史和取消机制接近，但承担了鲸栖自己的产品行为。

直接换成原始桥会丢失业务接线；官方重构源码后，字符串定位也可能失效。应优先评估由 DSH/Runtime 的公开扩展点承担这些行为。**运行在我们自己的插件包里，不等于实现已经不依赖官方内部结构。** 原始固定资产与生成后的改造产物须分开追溯，不能一概当成已篡改官方安装目录。

### 4.4 当前显式屏蔽官方附带 Web App

构建器只保留 Runtime 能力，并移除 Managed Web App 依赖；运行时对官方附带 Web App 的注册使用空实现。[分发构建](../../scripts/build-distribution.mjs)、[Runtime 包装](../../src/runtime-extension.mjs)

这用于保持当前产品入口，但也意味着不能把官方 Exposure 一打开，就认定它会接管现有通话和歌曲网页。直接恢复原贡献可能多出官方 DSH Web 入口；这属于可见功能变化，需要按现行产品要求评估。

### 4.5 对内部状态、目录和控制面的依赖

[clawchat-state.mjs](../../src/clawchat-state.mjs) 只读查询连接器 SQLite 的绑定、主人、就绪和工具结果；[clawchat-core.mjs](../../src/clawchat-core.mjs) 读取插件锁文件，调用云端状态命令和本机插件管理控制面；Liveware 进程也读取当前插件选择。

这些读取不会改写官方消息数据库，也没有另造消息传输，因此不能与改 Core 等同。但是官方改变表结构、命令、目录或管理协议时，仍可能需要适配。集中这些依赖、保留身份核验是正确方向；把查询散回业务、直接读登录令牌或自建第二连接，不是有效清理。

## 6. 清理必须分清三种动作

1. **只删补丁文件：** 测试机仍跑旧的定制程序，运行上没有完成清理，还可能失去可重建来源。
2. **直接换回纯官方程序：** 当前调用方仍请求这些入口，会出现媒体、二维码、通话、表情或结果查询等功能缺失；是否影响整体启动还取决于启动配置是否成套切换。
3. **先迁移调用，再切换运行程序：** 才是保持功能前提下的清理。调用、认证、会话、回执和启动路径必须一起验收。

这是先做适配再删除的原因，不是“这些修改不能清理”。目前没有证据支持“全部必须永久保留”，也没有证据支持“现在直接删除可以不改变功能”。

## 7. 建议的处理顺序与验收条件

本节是待决实施顺序，不代表已获得功能改动或部署授权。

| 顺序 | 目标 | 删除前必须看见的结果 |
| --- | --- | --- |
| 1 | 清掉确认无调用的旧查询方法，维护完整改动清单 | 当前回归不变；来源与构建信息仍可追溯 |
| 2 | 将普通对话中的媒体基础动作接到官方工具 | 图片、语音、视频、歌曲文件、二维码、截图均可发送；原作品不丢，类型与时长正确 |
| 3 | 确定脱离聊天后的任务如何使用官方受控发送 | 歌曲后台完成、恢复、跨端发起等不依赖偶然活跃的对话；不降低官方权限检查 |
| 4 | 替代只读结果和权限入口 | 断线后的结果能核对，不重复发送；日记受众和发布/删除权限不被跳过 |
| 5 | 替代共享会话和正文确认回调 | 聊天/通话无并发写入；打断和恢复正确；正文失败不发表情，重启不补发两次 |
| 6 | 让官方生命周期实际接管应用中继及启动 | 两个入口仍可用，认证与重启可恢复；实际进程改为官方 Core，旧定制入口退出运行 |
| 7 | 再移除 Core 补丁、复制目录与源码文字插入 | 有可复现的纯官方组合验收，升级前后原账号、会话、历史、作品和未知结果全部保留 |

部分事项可以并行分析，但最终切换必须维护单一连接与单一会话写入者。移除版本门槛不等于这些验收已经通过。

## 8. 本轮验证与边界

已完成：

- 实机只读核对实际 Core 进程、启动配置、插件状态、文件摘要与当前健康。
- 从实际配置的官方更新源读取 `0.2.22`，核对下载包摘要，取得固定源码提交。
- 对当前补丁涉及的官方文件及研究引用文件做逐字节比较。
- 使用 `0.2.22` 原始发送执行器、合成文件和替身传输完成七项隔离验证：允许的主人对话发送；无活跃对话拒绝；工作区外拒绝；DSH 状态目录拒绝；工作区内软链接行为；ACK 超时和普通提交异常的分类区别。
- 静态核对六类接口的当前调用方、启动覆盖、宿主模型转换、Bridge 构建与内部状态依赖。

## 9. 只通过自有插件实现的可行性评估

本节回应用户的新前提：官方连接器与官方插件原件不修改，鲸栖通过官方支持的插件安装、配置和公开调用方式接入。评估采用更严格的收敛方式：也不以修改副本、直接查询私有数据库、依赖内部类或替换官方启动流程来绕过该前提。这里的“可以”表示存在合理实现路径，不表示已经迁移或实机验收。

### 9.1 可以收敛到鲸栖插件的部分

| 功能 | 自有插件承担什么 | 官方保留什么 |
| --- | --- | --- |
| 人格、记忆、心情、共同设置 | 业务规则、持久数据及管理工具 | 正常收发和宿主执行 |
| B 站、私人日记、兴趣和主动联系策略 | 内容处理、账号操作、预算与任务调度 | 获准消息发送；公开发布仍遵守平台权限 |
| 生图、写歌、保存及作品管理 | 平台模型调用、任务恢复、作品库、歌词和乐谱、页面与下载 | ClawChat 中的结果投递 |
| QQ 基本接入和聊天 | OneBot 接线、主人关联和业务处理 | QQ 网关程序仍独立；ClawChat 中的二维码按官方附件规则发送 |
| 普通聊天中的图片、音频、文件和视频 | 生成产物、受控快照及目标核验，按官方要求交接工作区文件 | 上传、类型映射、发送和 ACK |
| 手动及自动语音 | 音色、识别、合成、触发策略、音频文件 | 聊天中获准的音频发送 |
| 实时通话本体 | 网页、收音、识别、模型回答、合成、字幕、打断、重连和播放状态 | 通过公开 Runtime 接口接入；严格共享原私聊另见下一表 |
| 通话与文字共享人格、获准长期记忆 | 使用同一份业务状态 | 不需要为此借用 Core 的内部会话句柄 |
| 鲸栖更新 | 查版、主人确认、发行包及业务数据兼容 | 官方插件安装与切换机制 |

当前许多业务已经在鲸栖中。需要收敛的是它们调用官方能力的方式，而非重新编写全部业务。

### 9.2 有公开路线，但不能承诺已完整保留

| 行为 | 可行路径与尚待证明的部分 |
| --- | --- |
| 电话严格接续当前私聊的完整上下文、同一原生会话及切换状态 | 自有 Runtime 可接收官方 `start/prompt/cancel/close` 和原生线程回调，统一协调文字与电话。仍需验证首次通话、Core 切换当前会话、重启、排空与取消的一致性，不能把“同人格记忆”当成“同一个实时会话”。目前不判定永久不可实现，也不承诺无损。 |
| 正文确认后再发表情 | 官方输出流程会逐条等待投递完成。自有 Runtime 可准备两条有序输出，让官方先投递正文，再投递图片，减少对私有回调的需要。本轮使用官方 surface 与替身 ACK 验证了先后顺序及正文失败时不发送第二条；尚未验证真实媒体、业务使用记录、重启和未知结果恢复。 |
| 两个 Liveware 保持当前两个独立入口 | 官方 SDK 支持自有 Managed Web App，官方 Exposure 可负责暴露。但它对每个绑定选择一个应用，两个原样独立入口如何共享官方中继还需验证。一个私有应用中放通话、歌曲两页是候选体验变化，未获实施授权。 |
| 首次开通、默认头像、问候和自动恢复 | 这些业务可以留在鲸栖，头像和发消息也有官方工具；当前用来核对主人、就绪和历史回执的私有状态读取必须替换成受支持来源。未证明可以原样保留所有自动化时序。 |

顺序输出验证只证明官方能够承担发送顺序，不能证明现有自动表情已完成迁移。严格共享原会话应优先做最小验证，避免再次先承诺“通话全功能可无损”，后发现公开接口不能表达所需状态。

### 9.3 现有公开入口存在的明确缺口

| 现有行为 | 当前限制 | 在不侵入前提下的边界 |
| --- | --- | --- |
| 没有活跃 ClawChat 对话时主动发送附件，包括后台歌曲完成或部分图片补发 | 官方文件工具明确拒绝这种调用 | 可以继续生成、保存和提供网页下载，也可发送获准文字通知；自动把附件送进聊天暂不能按现入口原样保证。以作品链接或用户索取代替，属于功能调整，须用户确认。 |
| 发布前读取平台权限、临时允许窗口及动态受众 | 平台 HTTP 已有，当前公开 Connect 工具/SDK 缺同样的认证读取入口 | 私人日记保存和官方基础发布/删除能力仍在；现行完整预检查存在缺口。不能默认放行，或读私有令牌自行补接。 |
| 断线后只读核对已提交工具请求 | 当前公开 CLI/SDK 未提供与 `tool status` 等价的只读查询 | 自有插件可保存请求并保持未知、不自动重发；自动取得最终回执仍有接口缺口。重复提交命令不能直接当成等价只读查询。 |

这些是现有公开接口下的缺口，不是平台永久不能支持，也不代表整项写歌、日记或发图功能都必须取消。官方补充受控接口后可重新评估。

### 9.4 评估结论

大部分业务、通话的语音处理和网页可以留在自有插件；普通对话内的投递可以交回官方。最需要先验证的是严格共享原私聊，其次是两个入口的官方托管及完整表情恢复。后台附件、权限预读取和未知结果只读核对有明确的现行入口缺口。

因此当前不能承诺“所有功能完全不变，直接换成纯官方即可”。也不能用这些缺口倒推“所有功能都必须改 Core”。应先验证决定体验的最小路径，再让用户选择是否接受具体变化或等待官方接口。本节没有实施迁移、降低权限检查或更改产品基线。

## 10 用户确认的后续方向与缺口逐项分析

用户确认将对话内附件发送、正文确认后表情、双 Liveware 服务及中继接线、业务装载与模型/运行适配收敛到鲸栖，保留为后续优化方向；当前先讨论接口缺口，没有实施或部署授权。[开发队列](../MIGRATION.md#连接器收敛的当前收尾)已登记。

补充双入口的责任边界：官方选择器每绑定只自动托管一个 Managed Web App，不等于只能注册一个 Liveware。可由鲸栖贡献一个托管应用，让官方 Exposure 运行官方中继；另一个应用通过官方结构化命令单独创建、绑定和注册，两个业务服务由鲸栖管理。当前定制中继与官方 Exposure 均复用同一官方 agent 程序及账号级登录，启动参数没有应用 ID 限制。此处是收敛设计结论，仍需在实施时验收应用共存、认证变化、退出恢复和资源清理；不宣称已经切换成功。

### 缺口一：原对话结束后主动发送附件

**事实：** 官方 `clawchat_send_file` 从正在处理的 ClawChat 回合推断调用来源；没有活跃回合时明确拒绝。这里的“活跃”指连接器仍在执行一次消息处理，不是用户在线、WebSocket 在线、存在聊天历史或机器联网。官方源码注释说明 CLI 调用不携带可信的回合来源，因此不能仅凭业务传入的目标聊天或回合编号授权后台发送。依据为本报告 3.1 引用的 `send-file-policy.ts`，已有隔离拒绝验证。

**当前差异：** 鲸栖现有媒体入口先验证主人、目标会话和受控文件，再通过新增的 Core 工具发送；该工具没有官方的活跃回合检查。歌曲 `create` 提交后返回任务状态，稍后的 `tick/advance` 才下载和投递成品，可能已经脱离原回合。

**具体影响：** 后台歌曲生成和保存不受影响，但任务完成后自动将音频或附件送回 ClawChat 的行为缺少等价公开入口。脱离原对话执行的图片/二维码补发同样受限。普通对话内及时发图、语音或表情不因这个缺口全部失效。把快照移入官方许可工作区只解决文件位置，不能解决后台来源授权。

**现有边界内的路线：** 若保持原回合一直执行到任务结束，附件可在该回合内发送，但会延长回合占用，并改变先回复后后台送达的流程；这不是等价替代。后台生成后留在作品页，等待用户下一次索取，也会改变自动回传体验，未获批准。要保留现在的异步自动回传且由官方执行发送，需要官方开放能携带原授权来源、固定目标和任务身份的后台附件入口，或等价的受控任务回调机制。

本轮只更新计划与分析文档，未修改发送代码、保持回合开启、减少功能或改动测试机。其余三个缺口后续依用户讨论顺序继续分析。
