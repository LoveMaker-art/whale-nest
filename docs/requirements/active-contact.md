# 主动联系需求

已确认功能需求；对应[技术设计](../technical/active-contact.md)。实际部署、启用与验收以[STATUS](../STATUS.md)为准。

接收位置使用已确认的[全局主动消息首选平台](proactive-delivery.md)，不为主动联系另设一份平台偏好。以下补齐具体对话交互和状态表现。

## 1 已确认需求

| 编号 | 用户可见行为 |
| --- | --- |
| S-01 | 大肥鱼在主人空闲时自然问候、关心或分享真实见闻。没有B站活动或日记，也可以普通问候；没有可说的内容时允许沉默，不虚构经历。 |
| S-02 | 复用Aurabot原speakup的联系条件、选题及表达逻辑。QQ与ClawChat使用同一实例、一份联系状态，不各运行一套主动策略。 |
| S-03 | 继承同一伙伴的全局主动消息首选平台，默认ClawChat；QQ连接并明确关联主人身份后可切换。主动搭话、活动分享、B站提醒和日记通知使用同一选择，各功能不重复询问。一次任务只有一个目标。 |
| S-04 | 两端已验证主人私聊的真实互动共同更新空闲时间，避免主人在一端聊天、另一端仍主动打扰。此处共享时间信息，不共享两端聊天全文。 |
| S-05 | 生成内容可使用目标会话上下文、获准长期记忆、当前心情及有权限的真实经历；不自动引用另一端的私聊原文、即时图片或工具上下文。 |
| S-06 | 沿用北京时间09:00—22:00、空闲至少2小时、两次主动联系至少间隔4小时、每天主动联系合计最多2次。活动分享、日记推送等使用同一总限制，不按平台各给一份。 |
| S-07 | 沿用实例共同后台上限5次模型请求/天，包含记忆整理和原内部重试。条件检查本身不调用模型；开关关闭、暂停、时段不符、额度不足或目标不可用时不发起新后台模型请求。 |
| S-08 | 主人可通过现有聊天查看状态、开关、调整允许的时段和频率；修改接收平台时更新全局首选。关闭主动搭话不关闭记忆整理或其他功能的独立开关；全局暂停仍遵守现有伙伴暂停规则。 |
| S-09 | 默认自动联系关闭，首轮只联系主人。原自动追问、白名单联系及purpose能力保留，默认不启用；扩展这些范围时另行核对。 |
| S-10 | 生成和发送前都检查限制；重启保留用量、冷却及待处理结果，不重新生成或重发已完成任务。目标切换作用于后续任务，旧待发内容不自动转发。 |

后台上限是当前实例的运行配置，不是每个功能的新配额，也不等于平台余额或免费调用次数。修改接收平台不代表授权登录QQ或关联新账号。

### 对话操作

| 用户操作或场景 | 产品表现 |
| --- | --- |
| “开启主动搭话” | 开启本功能，告知目前主动消息接收平台和联系时段；不同时开启B站自动浏览、日记生成或追问。 |
| “关闭主动搭话” | 停止新的普通主动联系，并取消尚未发送的本类任务；记忆整理保留。 |
| “以后主动消息都发QQ” | 按全局规则核对并修改唯一平台偏好；主动搭话开关保持原设置。 |
| “只在十点到晚上八点找我” | 调整共享主动消息时段并说明新值；每日次数和模型额度保持各自限制。 |
| “现在你会主动找我吗？” | 按实际状态说明开关、接收平台、时段、每日联系次数及是否被暂停或额度阻断。 |
| 满足联系条件 | 原speakup选择问候、关心或真实见闻；生成一两句自然表达，并允许沉默。 |
| 用户回复主动消息 | 在收到该回复的平台继续正常聊天，并刷新共同互动时间，不自动启动追问。 |

首次使用保持关闭。联系人仍限于主人；日常问候不依赖已有B站或日记内容，也不假装完成了浏览、出门或其他活动。

### 等待与异常状态

| 状态 | 用户可观察结果 |
| --- | --- |
| 尚未到时段、空闲或冷却条件未满足 | 安静等待，查询时解释原因，不发送一条“现在不能主动找你”的额外通知。 |
| 生成过程中主人在任一关联端发来新消息 | 更新共同时间，发送前重新检查，避免另一端紧接着打扰。 |
| 没有合适内容或模型选择沉默 | 本轮不发送；不会把内部沉默标记原样发给主人。 |
| 额度耗尽 | 停止新的后台生成，查询时说明；普通前台聊天仍按原平台能力和余额规则运行。 |
| 首选平台暂不可用 | 保留平台选择，不自动换到另一端。 |
| 已生成但发送暂受阻 | 保留有效结果，恢复后复查；不为等待再生成同一条。 |
| 发送结果未知 | 保留原记录，查询时说明未确认，不自动重复投递。 |

开关、目标及异常状态通过现有对话查询与操作反馈呈现，不增加独立管理页面。

## 2 与原功能相比的改动

| 原实现 | 本项目的必要改动 |
| --- | --- |
| 原speakup按QQ主人、QQ互动时间和本机时钟判断 | 接共同主人互动时间和北京时间；保持原选题、随机计划与沉默表达。 |
| 原fire将提示交给QQ Hub | QQ保留原Hub执行，增加ClawChat现有Session执行出口；目标来自可信配置。 |
| 原speakup.json自存次数与计划 | 复用现有共享状态及额度，原计划时间继续使用；不新增第二份每日次数和冷却。 |
| 原模块独立定时检查；早期项目另有自写share分支 | 原speakup成为唯一普通主动联系触发入口；移除对应自写触发及分享提示分支。 |
| 原后台执行与平台发送 | 接已有后台请求门禁、持久任务及真实投递结果；保留原QQ发送能力，不把ClawChat发送成功当QQ成功。 |

日记生成、B站活动、语音、生图及平台专属动作遵循各自功能规格。本项不重写其业务，也不借接入主动联系开启其他自动功能。

## 3 验收条件

| 编号 | 通过条件 |
| --- | --- |
| S-A1 | 实际调用原tick/fire；缺少B站或日记资料时仍可自然问候，沉默结果不发消息。 |
| S-A2 | 同一实例只有一个speakup实例和一个普通主动联系触发入口；旧share生成分支不再执行。 |
| S-A3 | 任一关联主人私聊更新共同计时；时段、2小时空闲、4小时冷却、每日2次及5次后台额度在两端共同生效。 |
| S-A4 | 只向选定平台发送，不能选择未关联目标；另一端即时原文不进入本轮模型请求。 |
| S-A5 | 在创建模型调用前拦截关闭、暂停、超额和目标不可用；前台普通聊天及独立记忆整理仍按原规则运行。 |
| S-A6 | 重复tick、重启、发送中断和切换目标不造成重复生成或重复投递；真实回执、未确认及沉默分别记录。 |
| S-A7 | 保留旧日记、经历、历史任务及已用额度；人格、记忆、心情和ClawChat媒体的相关回归通过。 |
| S-A8 | ClawChat使用真实模型并核对原平台回执；QQ先验证真实SDK与可控网关，真实QQ联调在账号范围获准后单列。 |
